## D1. 「停止当前处理」无法真正停住运行中的 Agent

- 严重程度：P1
- 模块：电子化助理 / 输入批次 stop

### 复现

1. 登录预览，打开电子化助理，点「新建会话」。
2. 发送：`请用八段话详细介绍小团宝的发团、财务、合作伙伴分别能做什么。`
3. 出现「发送中」或「正在思考」、回复开始流式输出时，立刻点发送按钮上的「停止当前处理」。

### 期望

当前批次变为已停止 / 已取消，流式输出中断，不再继续生成完整回复。

### 实际

- 第一次：停止按钮已渲染，但在整个流式输出期间保持 disabled，无法点击，回复跑完。
- 第二次：按钮可点，点击后回复仍完整输出八段话，随后弹出错误 toast：`AI 辅助暂时不可用，请稍后重试或继续使用表单`。
- 从未出现「已停止」或「已取消」。

### 备注

解析资料卡住时点停止同样不停，会一直转到解析失败。与本次「模型正在生成」是同一操作、两种运行态，建议一并修。

## D2. 「新建会话」会把上一会话未发送的附件带走

- 严重程度：P1
- 模块：电子化助理 / 会话草稿与附件

### 复现

1. 打开电子化助理，当前会话输入框点「+」附上任意 PDF（例如 2.2KB 的线路草稿）。
2. 不要发送。
3. 点标题旁「新建会话」。

### 期望

新会话输入区为空，不带上一会话的附件。

### 实际

新会话标题已是「新会话」，输入框仍挂着 `sample.pdf 2.2 KB`，需手动点移除。

## D3. 模型流式输出期间发送第二条消息，没有进入「排队中」

- 严重程度：P1
- 模块：电子化助理 / 输入批次排队

### 复现

1. 新建会话，发送一段会跑较久的话（例如请详细介绍工作台每一块）。
2. 第一条仍在「发送中 / 正在思考 / 流式输出」时，立刻再发：`排队甲`。

### 期望

第二条以排队消息展示（此前资料解析中出现过：`排队中 · 1`、`当前处理结束后自动发送`、可点「编辑」撤回）。

### 实际

没有排队行，也没有「编辑」。第二条被当成下一轮对话处理，Agent 对「排队甲」发起追问（「这个说法我没太看懂…」）。

### 对照

同一套 UI，在「已上传 1 个，解析 0/1」期间再发第二条，排队 UI 是出现过的。问题出在「Agent 正在生成」这一段，不是排队功能整体不存在。

## D4. 思考过程向用户泄露英文推理和系统提示 / 工具名

- 严重程度：P1
- 模块：电子化助理 / 可见推理（思考过程）

### 复现

1. 新建会话，发送需要推理的业务问题（例如分析工作台含义，或在运行中再插一句）。
2. 展开时间线上的「思考过程」。

### 期望

展示给用户的思考是面向业务的中文简述，不出现内部工具名、系统提示原文、英文 chain-of-thought。

### 实际

面板中可见英文推理，例如 `Let me reconsider: the conversation context is about 小团宝工作台...`，以及系统提示片段：`根据当前 User 输入用中给出简洁、可执行的说明。User 明确要求创建发团时，调用 routeConversation 登记建团目标…`，并露出内部工具名 `routeConversation`、`propose_departure_creation`、`readConversationSource`。

## D5. 关掉「当前发团」上下文后再发送，chip 会自己挂回来

- 严重程度：P2
- 模块：电子化助理 / 当前页 pageLocator

### 复现

1. 打开任意已有发团详情（例：发团管理 → `XTB26080001`「2026年8月3日 A线：天吐喀伊」）。
2. 打开电子化助理，确认顶部有 chip「当前发团概览」。
3. 点 chip 上的关闭，或点「移除当前页面」。此时应出现「获取当前页面」。
4. 发送：`当前这个团叫什么名字？`

### 期望

本轮发送不带 pageLocator；chip 保持移除，除非用户再点「获取当前页面」。

### 实际

回答内容是对的（说会话里没有这个团、叫不出天吐喀伊）。但发送之后，「当前发团概览」chip 又静默出现在该会话上。

## D6. 带「当前发团概览」时询问团信息，两次均「处理失败」

- 严重程度：P2（需回归确认）
- 模块：电子化助理 / pageLocator + Agent 执行

### 复现

1. 打开已有发团详情（同上 `XTB26080001`）。
2. 确认助理顶部有「当前发团概览」。
3. 发送：`请读一下当前发团，用一两句话告诉我团名和状态。`

### 期望

根据当前页发团返回团名、日期或状态；失败时给出可读原因。

### 实际

约 45–60 秒后时间线为「处理失败」，无团名、无错误详情。立刻再试一次，同样「处理失败」。

发生在 2026-08-28 16:50 左右。当时预览 OCR 接口尚未对齐（见文末环境项），但本条请求没有附件，按理不走解析。修复 OCR 后未再复测，开发接手后请先按上面三步回归。

## 场景变异中表现符合设计的项（不必当缺陷）

| 场景 | 结果 |
|---|---|
| 工作台发送「帮我弄一下。」 | 出追问卡（创建发团 / 其他事项），不建任务、不出待审核 |
| 打开 `/departure/new` 空坐 10 秒 | 无「当前建团工作」chip、无任务卡 |
| 在新建发团页问「这个页面是做什么的？」 | 只做说明，不建团 |
| 关掉发团 chip 再问团名 | 不臆造天吐喀伊团名 |
| 一句里两个目标（建川西团 + 说逾期应收） | 追问先做哪一个，不直接出待审核 |

正向路径（此前已验证、本文不展开）：闲聊回复、会话历史切换、全局模式进出、明确建团目标可出任务卡和待审核（未点确认）。

## 已处理的环境问题（不必再当产品缺陷，供预览机备忘）

预览机宿主机 RapidOCR 原先只有 `POST /ocr`，小团宝 worker 调用 `POST /v1/parse`，附件会停在「解析 0/1」。已在 `/mnt/mydata/ocr/ocr_api.py` 增加 `/v1/parse` 适配，并让 api / workflow-worker 使用 `OCR_BASE_URL=http://host.docker.internal:8089`（`docker-compose.runtime-hotfix.yml`）。回归时 PDF 可正确抽取「赛里木湖 1 日 / 成人 240」；手写日报图能出日期和司导，姓名列因旋转手写仍不稳定。
