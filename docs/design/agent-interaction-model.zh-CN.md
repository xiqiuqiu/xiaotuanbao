# 小团宝 Agent 交互模型

当前设计 · 2026-09-07。以 [PRD #483](../prd/2026-09-07-business-object-agent-collaboration.md) 及其当前配套规格为准。本文表达交互组织，不重新定义业务字段或技术合同；已替换此前全局会话、强制完整表单及建团阶段前置的草案。

## 入口与三栏

业务对象是一等公民。用户从已有发团业务页面唤起助手；侧栏识别可见业务范围，接收文字与材料，查询已有事实、核实歧义。取消独立全局聊天入口。普通业务导航和人工表单继续保留。

无需先形成审核包，侧栏即可展开为同一会话的业务对象工作区：

| 左侧：业务对象 | 中间：协作会话 | 右侧：本次事项 |
|---|---|---|
| 对象摘要、发团信息/客源管理/执行安排/财务四分类、相关私有协作记录 | 输入、材料、解析状态、澄清、结果说明 | 事项列表 → 具体审核 → 组内编辑 → 确认结果 |

默认查看全部分类。分类是查看筛选，不拆会话、不授予权限。事项列表、审核、编辑和结果回看均保持左侧相同组件、字段顺序与布局。状态、版本、来源放在右侧，不加关系进度顶栏。审核区独立滚动，底部动作保持可见。

侧栏与工作区共享会话和未发送输入；收起、返回、切换分类均不确认或取消事项。普通导航到无关业务不得偷带旧上下文，明确关联业务入口才可延续同一协作并显示关联范围。相关会话是关系投影，不代表对象独占会话。私人协作只对本人可见，正式业务记录按业务权限共享。

## 材料到业务记录

```mermaid
flowchart LR
  A[已有业务对象] --> B[同一会话输入或上传材料]
  B --> C[提取与匹配]
  C --> D[核实缺失与冲突]
  D --> E[多个独立事项]
  E --> F[审核与组内修订]
  F --> G[用户确认当前版本]
  G --> H[正式记录与回执]
  H --> I[用户选择后续初始账款]
  I --> E
```

纯查询可以直接回答，不强制生成写入提案。上下文只定位业务范围，不能替代用户材料。未知不默认填零；生成候选不表示正式业务已创建。结构化审核是唯一写入确认面，聊天不重复确认。

同次材料可形成同类或跨类多个独立事项。修订保留稳定事项身份和版本，已确认结果不能被后来候选覆盖。新材料不得覆盖正在编辑的字段；冲突只阻断受影响项。服务端持久受理多选确认，逐项回报；结果未知先回查，不能重建。

## 客源与资源

- 客源单按客户报价、团款调整、优惠、收款约定、业务备注与名单核对。每组保存仅改审核稿，确认后同组只读展示。
- 名单仅姓名必填，电话/性别/备注可选；不新增年龄、证件或电话类型。可只纳入完整名单，缺姓名候选排除并保留；不回写计费人数。
- 一张客源与选定名单共同成功或回滚。创建成功后才选择是否继续应收；适用正金额节点逐笔展示、整张客源整体确认。
- 资源使用现有八类、供应商、项目名称、总价、备注及业务归属；无需结构化数量、单价、容量。执行容量提醒不阻止合法费用录入。
- 日期仅为阅读分组。一条独立服务及其约定总价是确认单元；跨日整体费用归发团级并在备注写覆盖日期，不拆价。
- 资源成功后选择本次成功且未提交的资源，再独立审核初始应付。账款失败不回滚客源或资源。
- 财务分类聚合相关事项，不能混淆初始账款、实际流水与核销。本期不扩展历史账款修复、返利支付或全系统财务代理。
