## Comparison history

### Pass 5

- `P1`：审核内容与底部确认操作共用同一滚动容器，长内容滚动时“返回会话补充 / 确认创建发团”会离开视口。
  - Fix：右栏审核态拆为独立 `reviewScroll` 与固定 `reviewFooter`；滚动正文时两项操作持续吸底可见。

### Pass 4

- `P1`：删除评审状态轨后，原型默认直接进入审核，确认范围和 Agent 执行无法通过真实操作到达。
  - Fix：默认从确认范围开始；确认后自动进入执行，再由阻塞信息触发最小追问。
- `P1`：精确编辑仍使用覆盖页面的 Drawer，且保存后没有版本和重新校验反馈。
  - Fix：精确编辑改为右侧产物区一级状态；保存后提案版本递增并显示“已重新校验”。
- `P1`：会话追问与审核判断重复确认联系电话。
  - Fix：会话负责补齐联系电话；审核只判断“未锁定资源时是否先创建发团骨架”。
- `P1`：退出审核、会话发送和查看正式发团没有结果反馈。
  - Fix：补齐审核暂存/恢复、会话追加消息以及正式发团概览承接。
- `P2`：720px 高度下审核和编辑主操作落到首屏之外。
  - Fix：工作区固定为视口高度，内容区独立滚动，审核和编辑操作栏保持可见。

### Pass 3

- `P1`：WF-02 评审状态轨与“工作范围 → 来源会话 → 当前产物”关系卡重复表达页面结构，压缩真实工作内容。
  - Fix：两者均从业务页面删除；状态由页面内真实动作推进，三栏关系由固定布局和标题承担。
- `P1`：左栏会话标题与时间对齐不稳，窄栏下时间会换行。
  - Fix：统一列表间距，标题单行截断，时间固定单行展示。
- `P1`：完成态仍显示“待创建 / 草稿 / 退出审核”，会话切换也未更新中栏内容。
  - Fix：同步页头、对象卡和右栏完成语义，并让会话选择驱动消息内容。

### Pass 2

- `P1`：左栏“与 Agent 协作 / 直接填写表单”把进入前的双入口误做成工作区内模式切换。
  - Fix：删除该区块；完整表单仅通过右侧“编辑全部字段”按需打开。
- `P2`：删除区块后，“此草稿的会话”仍被 `margin-top: auto` 推到底部，造成业务导航与相关会话之间的大段无意义留白。
  - Fix：取消底部吸附，让“对象摘要 → 业务分区 → 相关会话”按阅读顺序连续排列。

### Pass 1

- `P1`：原生表单与 Agent 入口若继续分成两套页面，会让 User 不清楚正在编辑哪一份草稿。
  - Fix：两种入口收敛为同一“待创建发团草稿”的两种操作方式；表单以 Precision Edit 抽屉打开。
- `P1`：创建前没有正式业务对象，直接沿用 WF-01 的“已有对象”表达会产生错误心智模型。
  - Fix：左侧范围、页头和关系条统一改为“待创建发团草稿”，成功后再切换为正式发团。
- `P2`：WF-02 的状态故事仅存在文档里，难以验证跨状态连续性。
  - Fix：增加仅供评审的状态轨，覆盖确认范围、执行、追问、审核、写入和结果承接。
- `P2`：Ant Design 6 控制台提示 Drawer `width` 与 Timeline `children` 属性已弃用。
  - Fix：改用 Drawer `size` 与 Timeline `content`。

## Final review

- 三栏层级及业务对象、会话、产物关系与 WF-01 基线一致；
- 审核态主操作唯一，证据、影响和待判断项均在写入前可见；
- “直接填写表单”不会离开协作语境，保存后回到审核；
- 已浏览器走通 `确认范围 → Agent 执行 → 最小追问 → 产物待审核 → 正式写入 → 结果承接`；
- 已验证右侧精确编辑、保存返回审核、暂存/恢复、会话发送、确认创建和正式记录承接。
- 字体与层级、三栏节奏、Ant Design 语义色、图标来源和业务文案已逐项复查；无自制图形或占位资产。
- 实现截图由本轮 Codex In-app Browser 在 1280 × 720 逐状态捕获并检查；关键局部为左栏会话列表、右栏审核操作区和精确编辑底部操作栏。

## Residual differences

- 装饰性品牌图形未复刻 WF-01，避免把未确认的视觉资产固化进交互原型。
