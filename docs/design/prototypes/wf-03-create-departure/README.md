# 小团宝业务对象 Agent 协作原型

当前设计：2026-09-07，依据 [PRD #483](../../../prd/2026-09-07-business-object-agent-collaboration.md)、[客源规格](../../../specs/2026-09-07-agent-source-order.md)和[资源规格](../../../specs/2026-09-07-agent-execution-resources.md)。历史截图、旧建团流程及原型简化不覆盖最新规格。

## 运行与验证

```sh
npm install
npm run dev -- --host 0.0.0.0 --port 4173 --strictPort
node --test tests/*.test.mjs
npm run build
```

4173 是本地内存原型；5173 是真实系统。原型不调用真实业务 API，刷新会重置；生产设计要求持久恢复。`/source-order`、`/resources` 都由同一应用承接。

## 当前体验路径

1. 发团管理 → 打开已有发团示例 → 小团助手。无需创建新团。
2. 提供示例材料 → 名单与资源联合材料 → 查看原文并发送。只有完整示例模拟识别；任意自定义文本不会套用固定数据。
3. 展开协作，可在无提案时进入。左侧对象、四分类和相关会话固定，中间同一会话，右侧事项列表分别打开客源和资源。
4. 客源按报价、调整、优惠、收款约定、业务备注和名单组内编辑。取消不改稿；保存不写正式记录。名单可增删候选、编辑姓名/电话/性别/备注、选择本次录入；空姓名纳入时阻断，取消纳入后可继续。年龄及电话类型不作为字段或必答题。
5. 切换收款模式不自动挪用金额，同次编辑切回恢复草稿；代收为正且可超过结算额。创建客源成功后才出现继续应收，适用正金额节点逐笔展示、整单确认，不生成返利支付。
6. 资源按日期阅读、逐条选择。只编辑类别、供应商、项目名称、总价和备注；明细写备注。材料中的28座对照计划32人为提醒，不阻止确认2400元接送费用。零价或供应商类别不符阻断对应项。
7. 资源成功后选择后续应付，勾选本次成功的资源子集，再进入独立审核。不默认全选，不因创建资源自动生成账款。
8. 返回本次事项和结果回看，左栏形式保持稳定。正式业务页的原分区继续保留；按业务分类查看不拆分会话。

TXT/CSV 可以读取到输入区，PDF/图片/Excel 未接OCR或解析，不宣称已识别。名单原文的年龄仅保留在材料，不自动写入客人备注。电话不要求手机号格式，重复电话只提示不自动合并。

## 边界

一个示例团、一个客源模板和一组资源、单份当前财务提案；可演示多会话和跨类事项，但不代表任意同类多事项已经实现。目录、建团、增收、流水与核销仅为既有系统环境演示，不扩大 #483 首期范围。

真实客户/供应商检索、解析、人工修订与新材料冲突仲裁、服务端持久执行、权限、数据库事务、历史账款异常、跨设备恢复尚未实现。三家资源供应商仅静态匹配；资源按材料日期定位，发团级人工入口保留，跨日整体报价的 Agent 示例尚未覆盖。固定资源材料的容量比对属于只读提示，不是新增业务字段。
