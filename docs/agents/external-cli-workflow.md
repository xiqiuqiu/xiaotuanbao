# 外部 CLI 编码与 Codex 审核

适用于小团宝：外部 CLI 编码，Codex 负责派发、独立审核和验收。复用 GitHub 任务与本机命令，不新增编排服务。

## 任务与工作目录

1. 从 #483 当前附录及原生依赖读取有效要求。优先 #447；#456 可提前准备样例。一次派发一张票，不把整个 PRD 当成单次编码任务。
2. Codex 保存票据、规格快照、Git 基准 SHA 和工作区状态。开发使用独立 `codex/` 分支与 worktree；不让两个写入者同时修改同一目录。
3. 当前 PRD/规格含未提交文件，不能假设 worktree 自动带上。将本轮需要的文档与明确选定的本地变更复制到工作目录，记录路径和摘要；与基准代码的差异作为输入保存，不算 CLI 新产出。不复制生产凭据、真实客户材料或数据库配置。
4. 执行前准备开发依赖和隔离测试环境。worktree 不是安全沙箱；不启用全工具自动批准，采用受限权限，遇到权限阻塞由 Codex 检查具体操作。

## 派发合同

每次任务文件应包含：

- 当前票据正文、#483 与所需规格的本地快照路径，以及文档优先级。
- 本轮目标、允许变更范围、明确不做的事项和验收条件。
- 遵循 AGENTS.md；复用已有实现，必要时先 CodeGraph 定位代码。
- 不修改需求定义以迁就实现；不提交、推送、关闭票据、部署、重置数据或清理他人变更。
- 在 `implementation-result.md` 写明修改文件、实际测试命令与结果、未通过项及剩余问题；“未运行”不可写成通过。

Grok 帮助确认支持 `--cwd`、`--prompt-file`、`--output-format json`、`--resume`、`--max-turns`、`--no-subagents`。已在临时空目录以 plan 权限、禁止使用工具的提示执行一次连通测试：退出码 0，JSON 返回 CLI_OK 及 sessionId，说明当前认证和模型调用可用。尚未验证编辑、命令执行或会话恢复。下列为编码调用模板，需先完成权限实测：

```sh
/Users/sigclr/.grok/bin/grok \
  --cwd "$task_worktree" \
  --prompt-file "$task_prompt" \
  --output-format json \
  --max-turns 20 \
  --no-subagents \
  --permission-mode default \
  > "$task_result" 2> "$task_log"
```

Codex 保存退出码和返回的会话 ID。若非交互模式因权限停止，先核对日志及具体权限需求，不直接改为 bypassPermissions。修正使用明确 `--resume <session-id>` 加反馈文件，不用可能选错会话的 `--continue`，不使用 `--restore-code` 覆盖现有修改。超时/中断后先检查进程、差异与会话状态，不能马上启动第二个写入者。

Cursor 编辑器 3.19.13 已安装；此次未确认独立 Cursor Agent 可用。`cursor agent --help` 会自动安装缺失的 CLI，此次已停止该安装。完成独立 CLI 安装和登录核对后，可替换编码执行器；任务合同与审核步骤不变，不猜测其参数。

## Codex 独立审核 → 修正 → 验收

1. 对比派发基准与当前 diff，区分预先带入的变更，检查越界修改、调用链、权限、事务、幂等及恢复；不以 CLI 自述或退出码 0 代替代码审核。
2. 独立运行必要检查：`pnpm typecheck`；Web/shared 变更按仓库要求运行 React Doctor；权限面变更运行 permission-matrix。数据库相关检查使用隔离数据，数据库不可用不能算通过。不默认运行整套 API e2e。
3. 按票据覆盖实际业务闭环。#447 尤其验证同类多事项、版本冲突、多选受理后关闭页面、结果恢复；跨领域正式写入在对应接入票继续验收，不将旧测试通过描述成新功能完成。
4. 将问题按文件、复现、违反条款及预期行为反馈给原 CLI 会话；不增加无关重构。复审修正和受影响路径。连续两轮相同问题无进展时重新诊断，不无限自动重试。
5. 交付审核结果、代码 diff、测试证据和未解决项。用户授权提交/推送后再进入仓库规定的 Git 与 CI 流程；代码审核通过不自动等于可上线。
