# 业务对象协作工作区连接会话、事项与审核

当前决定 · 2026-09-07。本文件收口此前追加更新，替换独立全局聊天、默认完整表单和单阶段审核的早期描述。权威范围为 [PRD #483](../prd/2026-09-07-business-object-agent-collaboration.md) 及当前业务规格；既有权限、组织隔离、来源、金额和幂等保护保留。

## 决定

业务对象是一等公民。已有发团可直接发起协作，不依赖 AI 建团或行程新增。保留普通业务导航和人工表单，取消独立全局聊天入口。

侧栏和对象工作区是同一会话的两种视图，复用唯一会话壳、历史及输入。没有审核包也可以展开。左侧对象摘要、发团信息/客源管理/执行安排/财务四分类及相关协作记录；中间材料、澄清和消息；右侧事项列表、审核、组内修订及结果。确认与返回按钮吸底，内容独立滚动。左侧结构在事项、审核、编辑、结果间保持不变；不增设关系或阶段进度顶栏。

分类只用于查找，不拆分会话或扩大权限。会话与业务对象允许多对多关联，相关会话是本人可见的关系投影，不是全系统会话列表。普通导航到无关对象不偷带原上下文；显式关联业务入口才延续同一协作并显示范围。关闭/返回仅改变视图，不确认、归档或取消任务。

所有候选依据用户沟通、上传材料及受控已有事实。未知不归零，查询不强制建提案。用户在右侧审核当前版本，聊天不提供第二个写入确认。每项稳定身份、修订历史、来源与正式结果保留；同次协作允许同类及跨类多项。右侧事项为现有任务、审核包、命令及回执的投影，不另建权威待办系统。

客源按业务组就地编辑，保存只修订审核稿。名单只使用姓名、电话、性别、备注；姓名必填，不新增年龄/电话类型，完整且选定的名单随客源原子写入。团款计算、调整、优惠和模式语义按客源规格 Q1–Q6，不能从原型默认值推断规则。

资源按日期阅读、按独立服务及约定总价确认。沿用现有类别、供应商、名称、正总价及备注，不增加结构化数量/单价/容量。容量矛盾仅提醒执行风险，不阻止合法成本录入。跨日整体费用归发团级并注明日期，不强制拆价。候选修订、正在编辑、新材料、独立失败及共同前置失效按资源规格 R1–R25。

客源或资源成功后才由用户选择继续初始账款：同客源适用应收节点逐笔展示、整体原子确认；应付仅针对用户选择的成功资源逐项处理。账款不代表资金发生；历史账款异常不自动补建、恢复或覆盖。按对应普通操作实时授权，不使用通用发团写权限阻止合法初始账款操作，也不因此放宽客源/资源创建。

## 实施影响

以 [技术方案](../specs/2026-09-07-agent-collaboration-technical-plan.md) 第9、10节为准，复用现有 Worker、领域服务和审核包。服务端持久受理多选确认，每项业务写入与回执/幂等结果同事务；结果未知先查询，升级采用增量迁移，不清空旧会话或回执。

“待我处理”只聚合需要人工动作的事项，是入口投影，不是 Agent 全状态任务中心。首期对象范围内即可使用；全局 Inbox 不作为本期依赖。审核流程取消自动打开旧 Drawer，普通人工表单继续保留，不能把后者误删为旧路径。

## 未采用

- 独立全局聊天或 Agent 全状态任务中心。
- 会话永久归一个对象、每类别复制会话、单阶段只允许一包。
- 中间完整表单、右侧聊天；默认全表编辑；聊天重复确认。
- 从动作按钮凭空生成业务；缺省值冒充材料事实。
- 容量不足禁止录费、创建前选择账款、清空数据代替恢复。
