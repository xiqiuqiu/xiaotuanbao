# AI 候选在表单审核，聊天 HITL 等待处置

AI 阶段审核包由 Agent 经 `submitReviewPackage` 持久化为待确认候选，服务端审核包是跨刷新恢复的事实源。右侧会话通过 CopilotKit HITL 展示候选摘要、风险与「查看审核内容」入口，并等待 User 处置；高密度的候选查看、修正、确认与拒绝仍统一落在中间表单，聊天不提供第二套确认或拒绝按钮。

确认与拒绝均由 User 接口执行，不是 Agent 工具。确认成功后，前端以 `respond()` 将处置结果回传 Agent；Agent 重新读取最新任务上下文，回显已写入字段并继续询问当前阶段仍缺少的信息。拒绝成功后，Agent 仅回显本次建议已放弃且草稿未修改，随后等待 User 下一条指令，不追问、不主动重新整理或提交新审核包；只有 User 后续明确提出重新整理或新的修改要求时，Agent 才可再次提交。

版本冲突、权限不足或业务校验失败不代表审核结束：审核包继续保持待确认，HITL 不回传完成，User 处理问题后可再次确认或拒绝。关闭右栏、刷新页面或 Agent 运行超时可以结束旧运行，不影响表单处置；再次打开时创建新运行，并根据服务端草稿与审核包状态恢复协作。同一运行内的暂停与继续是在线体验优化，不是业务可靠性的前提。

文件、图片等多模态来源未来如何按业务对象或阶段拆分审核单元，由后续任务决定，本 ADR 不预设其事务边界。

**Considered Options**

- 不使用 HITL、Agent 提交后结束本轮：表单审核仍可靠，但确认结果不会自然恢复当前对话，割裂 Agent 协作节奏。
- 在聊天 HITL 卡片内完成全部审核和确认：窄栏不适合密集字段与证据编辑，运行时卡片也不能替代可跨刷新恢复的服务端审核包。
- 聊天与表单各提供一套确认按钮：产生两个权威入口，增加重复提交和状态分叉风险。
- 待确认值直接进表单并自动保存：未确认候选会进入业务快照。
