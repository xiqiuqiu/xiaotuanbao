# 发团误建删除：空壳物理移除，财务痕迹团只走关闭

计调需要纠正误建或误复制的发团，但不能与「已关闭」归档、Directory Archive（目录「删除」）混为一谈。决定引入 **Departure Purge（发团误建删除）**：仅当发团处于 `编辑中` 或 `待结算`，且无客源单、无任何收付款节点（含已作废/已关闭）、无任何曾归属本团的流水（含已作废）时，持 `departure:write` 者可物理删除该发团并级联清除行程段与资源草稿；产品文案为「删除」，列表与详情在不满足门槛时隐藏入口，二次确认即可、不填原因、不可恢复。发团编号按 ADR-0003 序列分配后不回收。已结清与已关闭发团不可 purge，只走关闭 / 解除归档。

## Considered Options

- **不做整团删除，一律关闭归档**：拒绝。误建空壳（尤其带复制行程草稿、尚未触客源与财务）若只能归档，会长期占列表心智，且与「已关闭＝业务归档只读」语义不符。
- **软删除 + 显示已删除/恢复**：拒绝。门槛已排除财务与客源引用；软删行无审计锚点价值，却与已关闭抢「还可找回」的心智，接近第二套归档。
- **物理删除并回收团号**：拒绝。团号对外可能已口头或文档引用；回收会造成新团复用旧号，违背 ADR-0003「生成后不变」。
- **仅无行程/资源的真空白壳可删**：拒绝。复制/常用路线建团的主误建场景几乎总带结构草稿，过严会使 purge 形同虚设。
- **有作废节点或作废流水仍可删**：拒绝。作废/关闭本身证明已介入该运营容器；purge 不是财务纠错通道。
- **仅企业管理员或仅负责人可删**：拒绝。第一版不做数据级权限；业务门槛已锁死财务痕迹，权限与新建/复制同为 `departure:write`。

## Consequences

- 列表「增」入口维持现状（新建向导 + 行内复制；班期生成仍在产品中心）；复制范围另见 ADR-0051。
- 后端删除必须重检门槛；前端隐藏不可删入口，但不替代服务端校验。
- 深链已 purge 的发团返回不存在；不提供恢复与删除原因审计表（第一版）。
- 领域词汇见根目录 `CONTEXT.md`（Departure Purge）。
