# 发团概览采用经营主指标与财务明细双层口径

发团概览主层面向快速经营判断，固定展示总人数、结算应收、成本合计、当前毛利、原始团款、优惠合计、毛利率、收款进度、付款进度与资金情况；财务确认口径与守恒异常不再占据主卡，但必须在对应指标的明细入口中保留。这样既避免概览被账款差异淹没，也不因界面简化而把业务源金额、财务确认金额和现金事实合并成同一套数字。

主层收款进度只计算客源路径已核销金额÷结算应收，其他应收留在明细；主层付款进度只计算资源应付已核销金额÷成本合计，手工应付、其他应付、资源账款差异及全部已付÷确认应付留在财务明细。关闭收付款节点不删除有效客源团款、资源成本或历史核销，退款反向流水第一版只按实际资金方向影响资金情况，不自动冲减收付款进度。

## Consequences

- ADR-0004 的 Finance Facade、原子财务快照、守恒异常及经营事实与财务事实分层继续有效；其旧版概览展示与主付款进度含义由本 ADR 更新。
- 概览 API 须同时支持资源应付已核销金额和全部应付已核销金额，不得复用一个聚合值表达两种口径。
- 页面采用主指标、经营补充、收付与资金三层信息结构，视觉遵循根 `DESIGN.md`；财务对照按指标就近展开，不新增独立财务对照大区块。
- 毛利率、收款进度、付款进度四舍五入固定显示 1 位小数（如 `80.0%`）；分母为零显示「暂无数据」。主层与经营补充的指标金额为零时显示 `¥0.00`；明细入口内的提示项金额为零时省略该行，使提示只在有事可说时出现。比例文字保留负数或超过 100% 的真实值，进度条仅在视觉上限制为 0–100%。
- 主付款进度分子取财务核销事实、分母取业务成本事实，属于有意的跨口径对比：资源账款差异不为零时进度可合法超过 100%，存在尚未生成应付时进度系统性偏低。两者都不是数据异常，由付款进度明细入口解释，不做截断或修正；实现时须为这两个场景保留测试用例。
