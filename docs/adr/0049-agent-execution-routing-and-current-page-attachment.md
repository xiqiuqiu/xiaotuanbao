# Agent 执行路由不靠当前页附件选定义，续执行留在同一输入批次

ADR-0048 已规定确定性关联优先、登记意图由服务端映射。统一会话壳落地后，最容易走的捷径是：用页面 `kind` 或 `/departure/new` 直接选 Agent 执行定义，或为建团单独做一条隐藏任务附件。那会让每个新业务页再分叉一套附件，并把路由器写进领域适配器。

决定：

- **Agent 当前页附件** 是各业务页唯一的 User 机制（默认附上、可移除）。工作台、列表、尚无 AI 建团任务的新建发团页不附上。不为建团做隐藏 `taskId` 或第二种附件条。
- 服务端将附件解析为 **Agent 页面上下文**（已持久对象，只收窄能力授予）或 **Agent 运行任务引用**（新建发团已有任务时作为 primary）。页面上下文与当前路由不得选定 Agent 执行定义。
- 无任务时走缺省通用定义；只有明确建团目标才产生 **Agent 任务创建提案**。打开新建发团页不是目标。提案成功后新任务记入本 **Agent 输入批次** 的 `created` 引用，当前 **Agent 执行尝试** 结束，控制面立刻在同一批次开启下一次尝试；不为续执行另开无 User 消息的批次，也不伪造第二次发送。
- 本批次已有 primary 时不因登记意图改选定义。跨领域只读通过移除当前页附件，或换到没有该任务附件的页面发送。
- 执行路由是平台模块。当前阶段只登记缺省通用与建团目标；合作伙伴账款查询只追加一条映射，不在领域适配器内硬编码路由。

## Considered Options

- 用 `locator.kind` 或当前路由选择执行定义：合作伙伴页上的建团意图会进错专长，新建发团页又没有对象 locator。
- 建团走隐藏任务引用、其他页走 chip：违反单一会话形态，供应商等后续页会再复制一套附件。
- 提案成功后新开无 User 的输入批次，或把原文再投递一次：破坏「批次来自一次 User 发送」，并伪造发送。
- 有 primary 时仍按意图改选只读定义：让登记意图覆盖确定性关联，路由器变浅。

## Consequences

第二业务竖切必须等平台执行路由能选择无任务 Definition 之后再加 Partner 映射与能力；不能把路由写进账款适配器。词表见 `CONTEXT.md` 中 Agent 当前页附件、Agent 执行路由、Agent 登记意图、Agent 任务创建提案。
