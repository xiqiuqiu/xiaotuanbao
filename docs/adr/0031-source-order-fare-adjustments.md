# Source Order fare adjustments alongside lump-sum discount

客源单在整单「优惠方式 / 优惠金额」之外，增加结构化 **团款调整项**（系统规范名；客户口头「附增项」不用作 UI/领域名）。结算金额 = 原始团款 + 调整净额 − 整单优惠，且必须 ≥ 0。调整项与优惠并存、不互相取代：明细加减（单房差、门票已优惠过等）走调整行；笼统整单让利仍走原优惠。列表/概览/合作团单/确认单与运营表只露调整净额；种类明细仅在客源单抽屉。调整项属金额事实，与人数、单价、优惠、收款拆分同一套 finance-touched 锁定与同步。

## Considered Options

- 用团款调整项取代整单优惠 — 客户仍需笼统让利入口，且「已优惠过」类减项与整单优惠易混，否决
- 规范名沿用「附增项」— 列表含减项，名不副实，否决
- 金额用正负号表达方向 — 录反风险高，否决；改为方向枚举 + 正数整行金额
- 第一版 Organization 可配置调整名录 — 当前客户清单稳定，后置；先用系统内置种类
- 概览分列增项合计/减项合计 — 第一版用调整净额即可，分列可后置

## Consequences

- 固定种类（方向锁死、每种最多一行、按需添加、金额 > 0）：单房差/儿童门票/续住（增）；学生门票已优惠过/儿童半价门票已优惠过/老人免票已优惠过（减）；自定义（方向自选、可多行）
- 「优惠合计」口径不变，仍只汇总整单优惠，不含减项类调整
- 历史客源单无调整项，行为与现网一致；新建/编辑才写入调整行
