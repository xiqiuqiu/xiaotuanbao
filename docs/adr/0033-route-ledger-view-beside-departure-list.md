# 发团管理并列「线路视图」，以客源单按路线名与出团日组织只读总览

客户习惯用「同一线路 → 按出团日分块 → 客源流水」的表格扫读人与钱的流向；现有发团业务主列表以 Departure 为行、扁平分页，无法承接该心智。决定在发团管理内增加与 **发团视图** 并列的 **线路视图**（见 `CONTEXT.md` Route Ledger View）：必须先按发团 `routeName` 精确归组选定一条线，再按所属发团出团日期分块；明细行是客源单（非发团）；同日多发团时先发团小标题再列客源。拼出资源成本与供应商挂在日或发团汇总，不写入客源行（系统无客源↔拼出分配关系，第一版不新建）。金额列为客源约定口径（只读拼入价算式、原始团款、结算金额、客户已收、我方代收、备注），列名用规范名并可 tooltip 附注习惯称；不做行级「实收业务」，不混核销已收；视图只读，编辑跳转既有发团/客源路径。

## Considered Options

- **只改发团列表列与分组**：行仍是 Departure，无法稳定呈现客人/拼入算式/按客源收款拆分，放弃。
- **客源行内硬挂拼出（复刻 Excel 同行）**：多客源×多拼出无 1:1 事实，分摊或猜测会制造对账争议，放弃。
- **第一版按 Product / 常用路线实体选线**：发团与模板/产品复制后脱钩，补永久关联范围过大；先按 `routeName` 精确归组，接受改名即新线。
- **行级「实收业务」净利**：口径未统一且常暗含摊拼出成本；第一版用日/团汇总表达当日结果，宁缺毋错。

## Consequences

- 需独立读模型/API（按路线名 + 出团日聚合客源，并附发团与拼出汇总），不能仅扩展现有 `GET /departures` 列表列。
- 与 ADR-0002（发团非结算单元、收入在客源、成本在资源）及往来账确认单的习惯名豁免边界一致：线路视图是系统 UI，规范名为主。
- 不替代发团运营表（单团总账本）或合作团单/往来账确认单（按 Partner）；线路视图回答「一条线按日怎么走」。
