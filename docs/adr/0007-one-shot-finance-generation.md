# 财务生成一次性：已生成后不可再点生成

客源单「生成应收」与资源「生成应付」是一次性入口。仅「未生成」可触发；已有收付款节点（含节点已全部关闭）后，列表改为「查看应收 / 查看应付」，生成 API 拒绝二次调用。金额同步与客源缺失路径补建走编辑源事实保存，不靠再次生成。避免重复应收/应付与重复收款入口；相对旧的幂等重跑与「重新生成」按钮，这是刻意收紧。

## Considered Options

- **已生成且未收款时仍可点生成（幂等同步）**：拒绝。UI 持续邀请「再生成」，与「尤其已收款后绝不能再生成」同一条安全边界冲突；同步应走编辑保存。
- **仅 finance-touched 后禁止，待收/待付仍显示重新生成**：拒绝。资源侧曾出现「重新生成」，易造成重复操作心智；应收/应付应对称且更严。
- **节点全部关闭后回退为未生成并允许再生成**：拒绝。关闭是财务履历，不是「从未生成」；回退会再次打开重复建单入口。
- **关闭后允许删除源事实或再改金额并生成**：拒绝。已关闭仍视为有过财务痕迹：不可删、金额只读。

## Consequences

- 客源单应收状态 / 资源应付状态需能区分「从未生成」与「已关闭」；结清进度聚合忽略已关闭节点，仅全部关闭时进入「已关闭」。
- 「查看应收 / 查看应付」跳转本发团对应财务 Tab，预填往来对象筛选（应收为客源单发客客户，应付为资源对手方），并对该源事实关联的全部节点行做一次高亮闪烁（定位提醒，非选中态）；与源事实「查看 / 编辑」并存。
- 生成成功须 invalidate 对应财务列表缓存；发团详情 Tab `destroyOnHidden` 使再次进入列表重建，但仅靠挂载不足以在 `staleTime` 内保证最新数据。
