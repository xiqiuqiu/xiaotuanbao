# 有效财务节点一次性生成，未介入资源应付可作废纠错

客源单「生成应收」与资源「生成应付」对有效节点是一次性入口。仅「未生成」可触发；已有有效收付款节点（含已关闭节点）后，列表改为「查看应收 / 查看应付」，生成 API 拒绝二次调用。金额同步与客源缺失路径补建走编辑源事实保存，不靠再次生成。唯一例外是财务从未介入的误生成资源应付：允许将旧节点作废并保留完整审计，资源恢复未生成、解锁金额，修正后可生成一个新节点。资源应付的作废与关闭入口严格互斥：未介入只可作废，已介入且未结清只可关闭。第一版不支持客源应收作废。

发团级「一键生成应收」与行程段级「批量生成应付」是对上述一次性入口的显式批量编排：仅处理尚未生成的源事实，逐条复用单条生成（含行锁），允许部分成功；已生成项不进入候选，金额不足等跳过。这与 CONTEXT 禁止的「批量自动生成」（保存即生成 / 后台静默批量）不同。应付批量按当前行程段收窄，不再提供发团级 `generate-payables`。

## Considered Options

- **已生成且未收款时仍可点生成（幂等同步）**：拒绝。UI 持续邀请「再生成」，与「尤其已收款后绝不能再生成」同一条安全边界冲突；同步应走编辑保存。
- **仅 finance-touched 后禁止，待收/待付仍显示重新生成**：拒绝。资源侧曾出现「重新生成」，易造成重复操作心智；应收/应付应对称且更严。
- **节点全部关闭后回退为未生成并允许再生成**：拒绝。关闭是财务履历，不是「从未生成」；回退会再次打开重复建单入口。
- **关闭后允许删除源事实或再改金额并生成**：拒绝。已关闭仍视为有过财务痕迹：不可删、金额只读。
- **用关闭处理未介入的误生成资源应付**：拒绝。关闭表达停止后续追付，仍保留有效确认义务；误生成应走独立作废语义，并从有效确认应付、进度及资源状态中排除。
- **同时支持客源应收作废**：后置。客源单可能同时生成客户补款与游客代收两条路径，单路径作废会牵动聚合状态、收款拆分与缺失路径补建，本次仅收敛资源应付纠错。
- **一键批量用前端并发调单条 API**：拒绝。并发生成曾导致重复节点（见财务可靠性审计）；正式能力用服务端串行批量 API（应收发团级、应付行程段级）。

## Consequences

- 客源单应收状态 / 资源应付状态需能区分「从未生成」与「已关闭」；结清进度聚合忽略已关闭节点，仅全部关闭时进入「已关闭」。
- 资源应付作废仅允许节点不存在任何核销历史（包括已撤销记录）、从未明确调整且尚未关闭；作废原因必填且最多 200 字，不设结构化类型，并记录作废前金额、操作人与时间。
- 资源应付列表与后端 API 使用同一 `financeTouched` 判断：未介入只开放作废，已介入且未结清只开放关闭，不同时暴露两个入口。
- 作废节点不参与确认应付、付款进度与资源应付状态；同一资源最多只能存在一个有效应付节点，重新生成必须由数据库约束与事务共同防重。
- 应付列表默认排除已作废节点，状态筛选增加「已作废」；作废节点仅在用户主动筛选后以只读审计记录展示。
- 「查看应收 / 查看应付」跳转本发团对应财务 Tab，预填往来对象筛选（应收为客源单发客客户，应付为资源对手方），并对该源事实关联的全部节点行做一次高亮闪烁（定位提醒，非选中态）；与源事实「查看 / 编辑」并存。
- 生成成功须 invalidate 对应财务列表缓存；发团详情 Tab `destroyOnHidden` 使再次进入列表重建，但仅靠挂载不足以在 `staleTime` 内保证最新数据。
- 发团级批量入口：`POST /departures/:id/generate-receivables`；行程段级批量应付：`POST /segments/:id/generate-payables`；响应汇总 succeeded / skipped / failed。
