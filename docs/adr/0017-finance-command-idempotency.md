# 财务写命令使用持久化幂等键

财务写操作可能因重复点击、网络超时或客户端重试被再次提交，而相同金额与对象也可能代表两笔真实业务，不能按 payload 本身去重。决定所有可重复发生、会改变财务事实的公开 HTTP 命令使用 `Idempotency-Key`：作用域为 Organization + operation + key；请求目标、规范化 payload 与操作者共同计算 hash。同键同载荷重放首次成功结果，同键异载荷返回 409，缺少 key 返回 400。客源应收/资源应付的一次性生成命令沿用来源行锁 + 来源唯一约束，重复请求明确冲突；它们没有“同来源再次生成”的合法业务含义，不另建请求重放记录。

幂等记录、业务写入和结果快照必须在同一数据库事务提交；同键并发请求先取得 transaction-scoped advisory lock，再读取或创建唯一记录。首个事务失败时记录随事务回滚，后续重试可重新执行；成功后重复请求不得再次分配业务编号或写入节点、流水、核销、Activity。第一版保留记录，不自动过期，优先保证财务重试在任意时间窗口都不会失忆；容量与归档策略有真实规模数据后另立 ADR。

前端为每次用户提交生成 UUID，并让同一次传输重试复用该 header。不同用户意图必须使用新 key；不能用“相同 payload”或短时间窗口猜测重复请求。
