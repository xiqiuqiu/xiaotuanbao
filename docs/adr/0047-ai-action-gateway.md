# AI 动作经统一网关先决策、先记录、再执行

ADR-0046 已把 AI 建团的执行生命周期从浏览器收到服务端：会话事件、不可变输入批次、PostgreSQL 工作流、Context Manifest 与表单审核 CAS。工具调用却仍是浅入口——服务身份与 AI 操作委托通过后，各 `*ForAgent()` 自行决定能否写入、要不要审核、失败如何留痕。扩展到客源、资源或财务后，规则会复制、旁路会增加，也无法回答「提出了什么、为何允许、谁确认、最终写了什么」。

决定在编排层与业务服务之间增加 **AI 动作网关**：Agent 只提出 **AI 动作**；服务端解析真实目标后决定允许、提交审核或拒绝；**无论结果如何先持久化决策，只有 `forward` 才调用领域服务**。没有决策记录的动作视为没有发生。本 ADR 不取代 ADR-0046 的可靠运行层，也不改变 ADR-0043 的表单确认面。

源码对照与「直接采用 / 抽象采用 / 不采用」见 [`docs/research/2026-openbot-agent-governance-lessons.zh-CN.md`](../research/2026-openbot-agent-governance-lessons.zh-CN.md)。该边界参考 OpenBot `govern()` 的 decide → record → act，但目标是领域对象而非浏览器元素，第一版策略是代码注册表而非 CEL。

## 三层边界

| 层 | 职责 | 权威 |
|---|---|---|
| Durable Workflow（ADR-0046） | 会话、批次、作业、attempt、Context Manifest、跨设备恢复 | 这次运行用了哪些输入、能否在页面关掉后继续 |
| AI 动作网关（本 ADR） | 解析目标、User 权限、AI 动作能力、风险、重复观测、决策审计、是否执行 | 这次工具调用该不该变成业务事实 |
| 业务事实 | NestJS 领域服务、对象版本、组织隔离、财务命令 | 最终能否写入；网关通过不降低原有校验 |

Context Manifest 回答模型看见了什么；AI 动作回答提出了什么。两条证据链都要，不能互相替代。系统提示词、技能说明和 `availableCapabilities` 提示字段不赋权。

## 网关不变量

顺序固定，与 OpenBot `govern()` 同构：

1. **解析 Actor**：从 AI 操作委托读取 User、Organization、任务、会话、批次、attempt、Context Manifest；委托无效即拒绝。
2. **解析目标**：按动作声明的 `targetType + targetId`（或任务内隐含目标）由服务端加载真实对象并校验 Organization。模型 payload 中的组织、权限、对象版本最多当提示，不能当证据；对不上则拒绝，并仍留下决策记录。
3. **查注册表**：未注册动作拒绝。缺策略、坏规则、未知动作均为 fail-closed，不得默认放行。
4. **查 User 权限**：复用现有 Menu Permission / Action Permission（ADR-0023）。User 现在无权则拒绝；网关不扩大权限。
5. **查 AI 动作能力**：当前任务/阶段是否授予该类动作。与步骤 4 是两个问题：有权的 User 也不表示 Agent 可代表其提出该类动作。
6. **业务前置条件**：对象版本、已有待确认审核包、任务状态、财务介入锁等，仍由领域规则定义。
7. **风险分级**：R0 只读默认允许；R1 草稿写入可自动或条件审核；R2 普通业务写条件审核；R3 财务写强制审核；R4 不可逆操作强制审核并展示明确影响。第一版等级与默认处置写在代码注册表，不引入 CEL，也不提供 Organization 级策略后台。
8. **重复观测**：fingerprint = 动作名 + 目标 + 规范化输入哈希（不含自由文本全文）。检测器只写观测行，**自身不拒绝**；是否拦截由注册表阈值决定。观测行丢失不得阻断决策行。它不是 Worker 作业重试计数，也不是 AI 活动运行预算。
9. **持久化决策**：允许、审核、拒绝都先写 AI 动作记录，带机器可读原因。`allowed` 与 `forward` 分离：观察模式下策略照算、审计照写，仍按接入前逻辑执行。
10. **`forward` 时才执行**：调用现有领域服务。执行失败补写结果行，不得把「决策允许」读成「业务已发生」。敏感字段只存安全摘要与输入哈希；审核包全文、证件号、密钥不得进入决策 payload。

只读动作（读任务上下文、搜常用路线、读发团资料解析结果）也走同一入口，因为仍有 Organization 隔离。它们通常为 R0、不产生审核；差别在决策，不在绕过网关。OpenBot 把浏览器 `snapshot`/`read` 旁路策略，不适用于小团宝的读工具。

人工表单保存、User 确认/拒绝审核包的 HTTP 命令第一阶段**不**进入网关。网关约束 Agent，不拦截人。人在手工编辑或审核未处置时，Agent 不得覆盖对应字段，也不得把未执行动作排队到人松手后自动回放。

## 审核与现有审核包

Gateway 决定 `REVIEW` 时，第一阶段仍物化为 **AI 阶段审核包**；查看、修正、确认与拒绝只在中间表单完成（ADR-0043）。Agent 不再自行决定「这次要不要审核」。聊天只展示等待审核状态，不提供第二套确认入口。多设备以审核包版本 / CAS 保证首个处置生效；拒绝后等待 User 下一条明确指令，不自动重做。

后续可将审核包演进为通用动作审核，但迁移期必须保持单一服务端事实源。禁止网关审核与旧审核包两个确认入口并存。

## 必须收编的旁路

凡会改变业务事实或产生待确认候选的 Agent 路径，都必须穿过网关。当前已知旁路：

- `AiToolController` 四个 `/api/ai-tools/v1/*` 在 Guard 通过后直调 `*ForAgent()`。
- `AiWorkflowProcessor.persistReviewPackage()` 在 headless 结果返回后直接写入审核包，不经过工具 HTTP。

观察模式若只包 Controller、不给 Worker 直写打预测决策，审计覆盖率无效。目标态：审核包只作为网关 `REVIEW` 的持久化投影；Worker 只消费已有动作身份，不再自行 insert 审核包。

禁止在 `apps/agent` 或 Mastra `createTool()` 内做权威允许/拒绝。Agent 进程可以失败，不能成为治理真相。

## 幂等

Worker 仍是至少一次执行。AI 动作身份在创建后不可变，AI 发起的业务写命令以该身份作为稳定幂等来源（`agent-action:{id}` 或领域等价唯一约束），扩展 ADR-0017：同身份同载荷重放首次成功结果，同身份异载荷冲突。目标是 at-least-once 执行 + 幂等动作 = 业务效果有效一次。重复 OCR 或模型调用仍可能发生并产生费用，但不能产生第二份有效审核包或第二套业务编号。

## 第一阶段交付边界

- 不替换 Mastra，不引入 LangGraph / 一 Agent 一浏览器 / gVisor / CopilotKit Intelligence 作为会话真相。
- 不重写 AiConversation、AiInputBatch、Workflow Worker、Context Manifest。
- 先观察模式接入现有 AI 建团工具（含 Worker 审核包直写），不改变当前允许/拒绝行为；稳定后再按 R0/R1 → R2 启用强制。R3/R4 财务与不可逆写在强制模式稳定前不得作为 Agent 可执行路径开放。
- 默认拒绝未注册动作。不得照搬 OpenBot shipped `allow: ["true"]`。
- 完整动作目录后台、组织级策略 DSL、通用动作审核改名、协作控制权的独立状态机、Agent Runtime Adapter 均后置，但不得违反本 ADR 的入口、审计与 fail-closed 边界。

## Consequences

- 每个产生业务影响的 Agent 调用都能回答：谁提出、对哪个真实对象、按哪条注册规则、允许/审核/拒绝、是否真正执行、与哪次批次和 Context Manifest 相连。
- 新增工具的默认路径是注册动作并走网关，而不是在 Service 里复制一套权限与审核分支。
- 代价是多一次决策持久化，以及观察期与旧写路径并存的纪律；换来的是财务级动作可被拦住，而不是先散落到各个工具再补审计。

## Considered Options

- **继续让各 Tool Service 自行治理：** 实现小，但客源/资源/财务会复制规则，且 `persistReviewPackage` 这类旁路无法被单一测试证明「拒绝到不了写入」。
- **把 CopilotKit / Mastra 工具层当网关：** 编排进程崩溃或被绕过时没有权威记录；权限撤销后仍可能「看起来记了」。
- **第一版引入 CEL 或组织级策略后台：** OpenBot 用 CEL 是因为网页目标空间开放。小团宝写动作是封闭目录，代码注册表接口更小、可测；DSL 是后置需求。
- **照搬 OpenBot 默认放行 + 浏览器 computer：** 会把 fail-closed 做反，并引入与发团表单无关的运维面。
- **观察模式只接 HTTP 工具、不接 Worker 直写：** 主写路径仍无决策行，审计是假的。
- **让全部人工表单写操作也走网关：** 扩大最终一致性范围；本 ADR 只治理 Agent 发起的动作。
