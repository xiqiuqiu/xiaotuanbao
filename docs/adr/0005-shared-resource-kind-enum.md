# 资源种类与供应商类别共用 ResourceKind，供应商为多选

执行安排的 **资源种类** 与供应商档案的 **供应商类别** 是两个概念，但共用同一套取值（规范类型名 `ResourceKind`）：用车、酒店、导游、门票、餐、景区、购物店、演出、保险、拼出、其他。删除独立的 `SupplierCategory`；同义旧称收束为统一 label（车队→用车、餐厅→餐、票务→门票）。拼出存值 `outsource` 可写入供应商类别（供应商 UI label「旅行社」；资源种类 UI 仍为「拼出」）——见 ADR-0032。

供应商类别改为 **非空多选、无主类别**，以支持一家供应商同时提供多种资源（如酒店兼餐）。列表与资源抽屉按「类别集合包含所选资源种类」筛选；保存非拼出资源时校验 `resourceKind ∈ supplier.categories`；切换资源种类时若新种类仍属于当前供应商集合则保留供应商，否则清空；编辑供应商类别时不得移除仍被关联资源行使用的种类。开发阶段按新标准重建测试数据，不做旧枚举双轨兼容。

## Considered Options

- **两套枚举 + 映射筛选**：拒绝。选项与 label 持续漂移，计调感知「种类不一致」。
- **合并成单一概念（两边都叫资源类型）**：拒绝。档案「能提供什么」与单次安排「用了什么」仍需区分。
- **供应商保持单选类别**：拒绝。无法表达酒店兼餐等真实案例；若放宽强制匹配又会毁掉按种类筛选。
- **改供应商类别时自动同步改写资源行种类**：拒绝。一家供应商下多种资源行并存时无法安全选目标种类；改为禁止移除仍被引用的类别。

## Consequences

- Prisma / shared 只保留 `ResourceKind`；供应商存储从单值 `category` 迁为多值类别集合；seed 与 demo 数据按新成员与多选重建。
- CONTEXT 中「Avoid: 与 resourceKind 共用同一枚举」已反转；后续实现以本 ADR 与 CONTEXT 为准，不以旧 PRD 中的解耦表述为准。
