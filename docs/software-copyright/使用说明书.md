## 1 简介

### 1.1 编写目的

本文档为「小团宝旅行社运营管理系统 V1.0」的用户使用说明书，说明系统定位、运行环境、主要模块及日常操作步骤，供产品使用、测试与登记材料交存使用。

### 1.2 使用对象

本文档主要面向旅行社企业内部的企业管理员、计调、财务及其他授权员工，以及负责部署与验收的技术人员。

### 1.3 产品范围

本系统是面向中小地接旅行社的 B 端 SaaS 管理系统，将散拼产品资料与班期报价、发团、行程执行、资源、财务、同行/客户、供应商及组织权限等业务收拢到同一套多租户平台中。

系统主要包含以下业务模块：

1. 登录与权限：登录用户名密码认证、角色菜单权限与操作权限控制。
2. 工作台：根据当前业务状态展示待处理事项，引导进入对应业务对象。
3. 发团管理：发团列表与详情、行程段、资源、客源单、执行与财务概况。
4. 产品中心：产品资料、班期与报价，支持由班期生成发团。
5. 合作伙伴：同行/客户等合作伙伴目录维护与业务引用。
6. 供应商管理：供应商档案维护及发团资源侧引用。
7. 财务管理：应收管理、应付管理、收支流水、核销管理。
8. 系统管理：组织信息与员工账号、角色绑定、启用停用。
9. 平台运营（平台管理员）：客户组织开户、启用停用、模块开通。

### 1.4 术语说明

1. Organization（组织）：使用本系统的一家旅行社租户单位，业务数据按组织隔离。
2. User / Employee（员工）：组织内可登录后台的人员。
3. 登录用户名：全平台唯一的登录标识，不区分大小写。
4. 发团：一次可执行的出团业务对象，承载行程、资源、客源与财务节点。
5. 客源单：发团下的客源与人数、价格相关单据。
6. 应收 / 应付：财务侧收付款义务节点。
7. 核销：将流水与收付款节点进行勾对确认的过程。

## 2 产品概述

### 2.1 总体框架

系统采用浏览器访问的 B/S 架构。用户通过桌面浏览器访问 Web 前端；前端经 API 网关/反向代理调用后端服务；后端访问 PostgreSQL 数据库，并可按需对接对象存储保存附件。多家旅行社组织共用同一套部署，通过组织标识实现数据隔离。

总体结构可概括为：

1. 表现层：Web 管理后台（页面、表单、列表、详情、权限菜单）。
2. 应用层：REST API 服务（认证、业务用例、权限校验、统一异常与返回格式）。
3. 数据层：关系型数据库持久化业务实体与审计所需字段。
4. 部署层：支持本地开发运行与 Docker Compose 单机部署。

### 2.2 系统架构与技术栈

1. 前端：Vite、React、TypeScript、Ant Design、路由与数据请求组件库。
2. 后端：NestJS、TypeScript、Prisma ORM、JWT 认证。
3. 数据库：PostgreSQL。
4. 工程形态：pnpm Monorepo，前后端共享类型定义。
5. 部署：Docker Compose；生产入口可由 Caddy 提供 HTTPS 与反向代理。

### 2.3 模块描述

#### 2.3.1 认证与权限模块

提供登录、退出、当前用户信息获取；按员工绑定角色解析菜单权限与操作权限；组织模块开通范围限制可见与可操作的业务能力。

#### 2.3.2 工作台模块

从发团、财务等业务状态实时派生待处理事项，例如资料待补充、待提交应收应付等，点击可进入对应业务页面继续处理。

#### 2.3.3 发团管理模块

维护发团主数据与状态，管理行程段、段资源与发团级资源、客源单与人数价格、执行概况及与财务衔接的信息展示。

#### 2.3.4 产品中心模块

维护可售产品与班期报价信息，支持基于班期生成发团，减少重复录入。

#### 2.3.5 合作伙伴与供应商模块

维护同行/客户类合作伙伴及供应商档案，供发团客源、资源采购与财务对象引用。

#### 2.3.6 财务管理模块

覆盖应收、应付、收支流水与核销，将业务约定金额与实际资金流转分开管理，并提供列表筛选与详情操作。

#### 2.3.7 系统管理与平台模块

组织内维护员工与角色；平台管理员维护客户组织名录、开户初始管理员及模块开通。

## 3 运行环境

### 3.1 硬件环境

1. 应用服务器：CPU 4 核及以上，内存 8GB 及以上，磁盘 100GB 及以上。
2. 数据库服务器：可与应用同机或独立部署，建议内存 8GB 及以上，磁盘 100GB 及以上。
3. 客户端：普通办公电脑，能流畅运行现代浏览器即可。

### 3.2 软件环境

1. 服务器操作系统：Linux 64 位（推荐 Ubuntu 22.04 及以上）或兼容容器环境。
2. 运行时：Node.js 22 及以上。
3. 数据库：PostgreSQL 16 及以上。
4. 可选组件：Docker、Docker Compose、Caddy。
5. 客户端浏览器：Chrome、Edge 等最新稳定版。

### 3.3 访问方式

部署完成后，用户在浏览器地址栏输入系统访问地址，打开登录页。首次使用前应由管理员完成组织开通、员工账号创建及角色授权。

## 4 使用说明

### 4.1 登录与退出

#### 4.1.1 登录

1. 打开系统登录页。
2. 输入登录用户名与密码。登录用户名在全平台唯一，无需额外填写组织标识。
3. 点击登录。校验通过后进入工作台或默认首页；失败时页面提示错误原因。
4. 若账号已停用，或所属组织已停用，则无法登录。

#### 4.1.2 退出

在系统右上角用户区域选择退出登录。退出后令牌失效，再次访问业务页将回到登录页。

#### 4.1.3 权限说明

1. 左侧菜单仅展示当前员工角色权限与组织已开通模块的交集。
2. 无权限的按钮与操作在界面中不可用或不可见。
3. 企业管理员在组织已开通模块范围内拥有对应管理能力。

### 4.2 工作台

1. 登录后进入「工作台」。
2. 查看待处理事项列表。事项由系统按当前业务状态自动生成，源状态解除后自动消失。
3. 点击某一事项，跳转到对应发团、财务或其他业务对象继续处理。
4. 工作台事项不是可手动勾选完成的个人任务，完成业务操作后事项会自动更新。

### 4.3 发团管理

#### 4.3.1 查看发团列表

1. 打开左侧菜单「发团管理」。
2. 在列表中查看发团编号、名称、状态、时间等关键字段。
3. 可按状态或关键字筛选，定位目标发团。
4. 点击发团名称或详情入口进入发团详情。

#### 4.3.2 维护发团基础信息

1. 在发团详情中查看或编辑发团基础资料。
2. 按业务需要补充出团日期、线路相关信息等。
3. 保存后列表与详情同步展示最新数据。
4. 发团编号由系统按组织业务前缀等规则生成，用户按界面提示使用，勿手工编造冲突编号。

#### 4.3.3 维护行程与资源

1. 在发团详情中进入行程相关区域，维护行程段。
2. 为行程段或发团级资源登记资源类型、供应商、约定金额等信息。
3. 资源信息将作为后续提交应付等财务动作的依据之一。
4. 若系统提示资料待补充，按提示补齐客源、行程或资源后再继续后续流程。

#### 4.3.4 维护客源单

1. 在发团下新增或编辑客源单。
2. 选择或关联合作伙伴（同行/客户），录入客人人数与价格相关信息。
3. 确保已录入客人数与客人人数等关键字段符合业务实际，避免资料缺口。
4. 客源侧信息可用于后续应收节点的生成与核对。

#### 4.3.5 发团状态与执行概况

1. 在详情中查看发团业务层与财务层概况信息。
2. 按权限执行关闭、结清相关等状态操作时，仔细阅读确认提示。
3. 高风险操作（如影响结算或不可轻易逆转的状态变更）需确认影响范围后再提交。

### 4.4 产品中心

1. 打开「产品中心」。
2. 创建或编辑产品资料，维护产品名称、行程结构等基础信息。
3. 维护班期与报价；报价可作为后续发团价格参考或快照来源。
4. 在具备条件时，由班期生成发团，减少从零录入发团的工作量。
5. 生成发团后，仍须在发团详情中核对行程、资源与客源是否完整。

### 4.5 合作伙伴

1. 打开「合作伙伴」。
2. 新建合作伙伴档案，填写名称、联系方式等必要信息。
3. 在列表中检索、查看、编辑档案；按组织规范停用不再合作的对象。
4. 在客源单等业务中引用合作伙伴时，仅可选择当前组织可见的有效档案。

### 4.6 供应商管理

1. 打开「供应商管理」。
2. 新建供应商，维护类型、名称、联系信息等。
3. 编辑或停用供应商档案。
4. 在发团资源中引用供应商，保证采购对象可追溯。

### 4.7 财务管理

#### 4.7.1 应收管理

1. 打开「财务管理 - 应收管理」。
2. 在列表中查看应收节点编号、关联发团/客源、金额、状态、到期日等。
3. 按状态、关键字或业务编号筛选。
4. 进入详情查看节点明细；按权限执行确认、调整、关闭等操作（以界面实际按钮为准）。
5. 操作前确认金额与业务对象无误，系统会保留必要的操作痕迹以便核对。

#### 4.7.2 应付管理

1. 打开「财务管理 - 应付管理」。
2. 查看应付节点列表及关联资源、供应商、金额与状态。
3. 对计调已提交的应付进行财务侧处理。
4. 注意应付与应收在逾期、到期日等规则上可能不同，以界面字段与提示为准。

#### 4.7.3 收支流水

1. 打开「财务管理 - 收支流水」。
2. 登记或查看实际收付款流水，包括方向、金额、日期、对方信息等。
3. 流水反映资金事实，与应收应付义务进度区分管理。
4. 可通过业务编号等条件检索，便于与核销环节衔接。

#### 4.7.4 核销管理

1. 打开「财务管理 - 核销管理」。
2. 选择待核销的流水与对应收付款节点进行勾对。
3. 确认核销金额与对象后提交。
4. 核销完成后，相关节点与流水的核销进度会更新，可在列表中复查。

### 4.8 系统管理

#### 4.8.1 组织管理

1. 打开「系统管理 - 组织管理」。
2. 查看本组织名称、业务前缀等档案信息。
3. 业务前缀用于生成发团编号及财务类业务编号，创建后按规则使用，避免无前缀时强行创建受限单据。

#### 4.8.2 员工管理

1. 打开「系统管理 - 员工管理」。
2. 新建员工：设置登录用户名、显示名称、初始密码、角色等。
3. 登录用户名全平台唯一且不区分大小写；保存前请确认无冲突。
4. 可编辑员工资料、调整角色、启用或停用账号。
5. 停用后该员工不可登录；停用不会释放其登录用户名。

### 4.9 平台运营功能（平台管理员）

以下功能仅平台管理员可见，普通旅行社员工无此菜单。

1. 登录后进入平台区（与租户业务后台分离）。
2. 在客户组织名录中创建组织：填写组织名称、业务前缀，并同时创建初始企业管理员（登录用户名、显示名称、初始密码）。
3. 创建后，初始企业管理员可登录租户后台开展业务。
4. 可对客户组织执行改名、启用/停用。
5. 通过「模块开通」配置该组织已开通的业务模块，保存后生效。
6. 平台区不提供删除客户组织，也不代替租户侧进行日常员工密码重置等管理（除非产品后续另行开放）。

### 4.10 常见操作建议

1. 先保证发团资料完整（客源、行程、资源），再提交应收应付，可减少反复退回。
2. 财务操作前确认业务编号与金额，避免对错团、错节点核销。
3. 员工权限变更后，请重新登录或刷新后再验证菜单是否更新。
4. 若页面提示无权限，联系企业管理员检查角色与模块开通。

### 4.11 异常与提示

1. 登录失败：检查用户名大小写无关但仍须字符正确，并确认账号与组织状态为启用。
2. 保存失败：根据页面错误提示检查必填项、唯一性冲突或状态限制。
3. 网络或服务异常：稍后重试；若持续失败，联系系统运维检查服务与数据库状态。
4. 并发或重复提交：部分财务命令具备幂等保护，仍应以界面最终状态为准，勿重复盲目点击。

## 5 维护说明（简要）

1. 日常备份：定期备份 PostgreSQL 数据。
2. 升级发布：按部署文档更新应用镜像或构建产物，并执行必要的数据库迁移。
3. 日志与健康检查：可通过服务健康检查接口确认 API 与数据库连通性。
4. 账号安全：定期审查员工启用状态与角色授权；勿共享管理员密码。
