# 客源单业务功能规格草案

版本：v0.3 · 2026-09-07。关联交互 PRD：[业务对象 Agent 协作 #483](https://github.com/xiqiuqiu/xiaotuanbao/issues/483)。

本文将现有业务字段映射到新交互，覆盖已有发团下新增客源单、待确认稿修订、名单录入及创建后初始应收承接。不改变三栏、对象入口、材料驱动、创建成功后才选择应收等已确认交互。不是旧建团 PRD 的延伸，也不据此要求业务先通过建团阶段。

规则标记：**已确认**指本轮用户已确认的交互；**现状基线**指本地代码核实的业务行为，作为本草案建议保留的规则，不等于整份旧 PRD 自动继承；第10节 Q1–Q6 已经用户明确同意推荐并确认。证据见文末；这不代表尚未完成的技术差距与财务承接核对已经通过。

## 1. 操作范围与状态

| 状态 | 右侧表现及操作 | 正式业务影响 |
|---|---|---|
| 材料待解析/失败 | 展示材料状态、重试或补充文字 | 无 |
| 待补充 | 展示已提取字段与问题；可回复或就地修订 | 无 |
| 待审核 | 五组摘要、来源及完整结算过程 | 无 |
| 组内编辑 | 编辑该组，取消或保存本组；确认暂不可用 | 保存只更新审核稿 |
| 确认提交 | 禁止重复点击；服务端重新校验目标、权限、版本和业务 | 一张客源单及本次名单原子写入 |
| 已创建 | 保留相同分组只读结果；查看正式记录或继续提交应收 | 此时还没有应收 |
| 后续应收审核 | 根据正式来源展示拟提交账款，单独确认 | 仅账款，不是实际到账 |
| 拒绝/失败/版本过期 | 保留来源、修改和原因；明确恢复/重新核对入口 | 不将未执行内容显示为成功 |

已确认：左侧业务对象面板在上述状态下保持同样结构。中间始终同一会话。新增材料不能覆盖人工正在编辑的组。已创建记录的修改不是对旧候选的静默回放，本草案不扩展具有财务履历的修改路径。

## 2. 字段通用约定

- 展示金额单位为元、最多两位小数；接口以整数分表示。以下所有金额规则在确认时由领域服务验证。超过两位的小数如何提示见 Q6，不静默损失精度。
- 字段标注来源：用户文字/材料位置、已匹配业务对象、人工修订或系统计算。缺失、明确为零和不适用必须分开；显示控件的默认值不表示用户已提供。
- 派生字段不可直接修改。人工可修改来源字段，保存本组后重算所有受影响摘要，并保留修订依据。
- 一个业务组的取消只撤销本次未保存编辑；保存本组不写正式业务。提交确认时仍校验整张客源单，不允许以分组保存绕过联动校验。
- 客源单基础字段写入 SourceOrder，调整行写入其关联明细，名单写入其关联客人；来源/不确定性与人工修订保留在审核记录，不冒充业务字段。

## 3. 客户与报价

| 字段 | 来源/可编辑性 | 现状基线与审核约定 | 写入/联动 |
|---|---|---|---|
| 目标发团 | 当前对象上下文，明确显示 | 服务端检查同一 Organization、对象存在、业务可编辑；不能仅凭模型 ID | 绑定发团；目标改变须重新核对整稿 |
| 客户 | 材料客户名经受控查询；人工可选择 | 必须匹配同 Organization 的有效客户。无匹配/多匹配待澄清，不自动新建客户 | partnerId；选择变更影响后续客户补款对象 |
| 成人人数 | 材料/人工；整数 | 必填、≥0 | adultGuestCount；重算人数与团款 |
| 儿童人数 | 材料/人工；整数 | 必填、≥0；成人+儿童必须>0 | childGuestCount；同上 |
| 成人单价 | 材料/人工；金额 | 成人人数>0 时必填，允许明确 0；人数为0时不要求，计算有效单价为0 | adultUnitPriceCents |
| 儿童单价 | 同上 | 儿童人数>0 时必填，允许明确0；人数为0时不要求 | childUnitPriceCents |
| 总人数 | 派生、只读 | 成人+儿童；不是名单行数 | 不从名单反推覆盖 |
| 原始团款 B | 派生、只读 | 成人×成人有效单价+儿童×儿童有效单价 | 影响结算金额与后续账款 |

材料没有提及儿童不能自动宣称儿童为0；如何让用户低成本确认缺失项见 Q1。客户姓名相同不代表客户 ID 相同。匹配新材料到已有客源单时，提示是新增还是修改，不自动重复新增。

## 4. 团款调整

| 调整类别 | 固定方向 | 行数规则 | 说明 |
|---|---|---|---|
| 儿童门票补款 | 增项 | 每类最多一行 | 可选说明 |
| 单房差补款 | 增项 | 每类最多一行 | 可选说明 |
| 续住费用 | 增项 | 每类最多一行 | 可选说明 |
| 门票优惠退差 | 减项 | 每类最多一行 | 可选说明 |
| 住宿费用扣减 | 减项 | 每类最多一行 | 可选说明 |
| 其他费用调整 | 用户选择增/减 | 可多行 | 必须填写调整说明 |

现状基线：每行 amountCents 为正整数，金额必须大于0；固定类别方向不可改，同类固定项目不可重复。kind、direction、amountCents、customName 为现有字段；不存在原型中任意项目名与独立说明两套权威字段。固定类别显示目录名称，customName 承载说明；“其他”的说明必填。

操作：添加、编辑、删除调整行；保存后计算调整净额 A=增项合计−减项合计。删除只删除候选行。尚未写入但信息不完整的行应保留待补充，不能作为0元正式调整提交。

材料出现两笔同类固定费用时，不能丢弃其中一笔，也不能直接创建两条被服务端拒绝的行；合并表达见 Q3。门票优惠退差属于调整，整单优惠属于下一组，不因都有“优惠”二字合并。

## 5. 团款优惠

| 字段 | 来源与约束 | 操作与影响 |
|---|---|---|
| 优惠方式 | 材料/人工；现有枚举 none、lump_sum | 无优惠或整单优惠；没有百分比折扣能力 |
| 优惠金额 D | 整单优惠时明确提供，≥0；无优惠有效金额0 | 影响结算，不影响原始单价 |
| 优惠备注 | 可选文字 | 保留业务说明，不改变金额 |

现状基线：计算与存储对 none 使用0。现有 API 能把省略优惠金额归为0，**不能据此把材料未提供的优惠当作已确认0**。新交互的缺失确认策略见 Q1；方式切换后旧输入保留规则见 Q2。

结算金额 S=B+A−D，必须≥0，允许为0。不得额外限制 D≤B，因为已有正向调整可能使可优惠基数大于原始团款；以最终 S 校验。零结算不意味着所有代收路径也为零。

## 6. 收款约定与结算说明

| 收款方式 | 编辑字段 | 有效客户已收 P | 我方代收约定 G | 约束 |
|---|---|---|---|---|
| 客户结算 partner_settled | 无代收定金/尾款输入 | S（现有业务派生展示） | 0 | 正式定金/尾款规范化为0 |
| 全部我方代收 guest_only | 我方代收定金 d、我方代收尾款 b | 0 | d+b | d、b 均非负，G>0 |
| 分拆收款 split | 客户已收定金 d、我方代收尾款 b | d | b | d、b 均非负，b>0 |

- 收款方式必须明确。代收模式下 UI 要求定金/尾款完整，明确0和空值分开；API 的兼容归零不作为材料事实。
- **不要求 P+G=S，不因 P>S 拦截，允许 G>S。** 不能使用原型“代收不超过结算金额”的简化限制。
- 代收模式预计客户补款=max(0,S−G)，预计返利=max(0,G−S)，P不参与这两个公式。
- 客户结算显示结算金额与“无代收轧差”；避免把通用计算结果机械显示成额外预计差额。
- 结算说明 settlementNotes 可选；业务备注 notes 独立可选，供免票/特殊要求等记录，不与优惠备注合并。
- 这里记录约定与业务派生值，不证明真实到账；不登记流水、不核销、不生成返利支付。
- 修改报价、调整、优惠或代收金额均重算差额；不得自动反算覆盖用户已确认的尾款以凑齐结算金额。

## 7. 客人名单

| 字段 | 现状类型与必填 | 新审核稿表达 |
|---|---|---|
| 姓名 name | 必填字符串 | 不能保存空白姓名，来源不明先补充 |
| 电话 phone | 可选字符串 | 保留提供内容；不强制大陆手机号格式，不能因座机就阻止确认 |
| 性别 gender | 可选，male/female/unknown | 未提供不从姓名推断；可选未知 |
| 备注 notes | 可选字符串 | 与客源单业务备注区分 |

现状基线：名单为备忘名单，不自动回写计费人数；仅姓名必填。不存在独立年龄、成人/儿童分类、证件号码、电话类型字段。原型“刘童童年龄6或7”“王强电话是否座机”的强制判断不是通用业务要求。新增字段须单独决策，不能悄悄扩表。

操作约定：可新增、编辑、删除候选名单行；只修改本次草稿。显示“客名单 N 人 · 客源单人数 M 人”，不把差异直接当作金额错误。重复姓名/电话只提示可疑，不擅自删除或合并，同名或家庭共用电话可能合法。名单不完整与未知扩展信息的确认策略见 Q4/Q5。

确认采用新 PRD 的原子边界：一张客源单与本次确认的名单共同成功或共同回滚。现有普通接口中客源单与客人分开创建，不能把前端顺序调用成功当作这一原子性已实现。

## 8. 校验分级与操作细节

### 阻断正式确认

- 权限不足、目标不属于当前 Organization、发团不允许编辑、客户无效。
- 人数缺失/非法/合计0，人数>0但对应单价缺失，负金额或不合法精度。
- 调整行金额≤0、固定类别重复或方向错误、其他调整缺说明。
- 所需收款约定缺失，或代收模式G≤0，或S<0。
- 本次要写入的名单行无姓名时不得写该行；按Q4明确排除并保留待补充后可继续整单确认；审核版本过期、编辑未保存、服务端校验失败。

### 提示但不凭空增加业务约束

- 名单行数与计费人数不一致、可疑重复、无电话/性别/备注。
- G>S产生预计返利；P+G不等于S本身不阻断。
- 非必填的未知原文信息不自动变成整单硬阻断，处理方式见已确认规则 Q5。

### 修订与确认

1. 展示候选摘要、问题与来源；选择组内编辑时保留已保存稿基线。
2. 保存本组后重算关联结果；无效字段保留并显示原因，不产生正式记录。
3. 新材料修订定位到这张候选；人工已修正字段与材料冲突时显式展示差异，不能最后写入者静默覆盖。
4. 确认只使用当前审核版本；写入成功才显示已创建。超时不能直接宣称失败或重建，应查询同次确认结果。
5. 失败保留稿件、原因和已有修订；重复确认不重复新增。拒绝提案不自动续建。
6. 已创建后查看结果使用正式保存值及处置记录，不用后来变化的样例或草稿覆盖历史。

## 9. 创建后初始应收

已确认：客源创建审核中不出现“是否提交应收”。成功后显示“暂不处理/查看客源单”和“继续提交应收”。继续操作准备独立财务审核，员工再次确认才正式提交。

现状账款路径如下（金额均只为正数时创建）：

| 模式 | 应收路径 |
|---|---|
| 客户结算 | 客户补款 S，收款对象为客户 |
| 全部我方代收 | 定金代收 d、尾款代收 b，收款对象为游客；若S−G>0另有客户补款 |
| 分拆收款 | 尾款代收 b；若S−G>0另有客户补款；客户已收定金不是我方定金代收 |

G>S时初始提交不建立返利节点；返利处理不在本期自动执行范围。无正金额路径时解释无需生成，不创建0元账款。生成前重新读取正式来源、权限和已有节点；重复点击不能重复提交。已有账款异常按 F2 处理，不自动补建、恢复或覆盖。

账款提交失败不回滚已经创建的客源单；显示“客源已创建，应收未提交”，允许按失败原因处理。跨业务的两个确认步骤不能伪装为一次全局事务。

### 初始账款补充决定（已确认）

- **F1 整体确认：** 一张客源单适用的各笔正金额初始应收逐笔展示，按该客源单整体确认，同事务全部成功或全部不写入；不允许在初始生成时任意取消其中一笔。可以整张暂不提交，不同客源单独立处理。
- **F2 历史异常：** 本期不做历史账款修复。已完整生成且与当前约定一致时展示已有记录；不完整、已取消、已作废或金额不一致时说明具体情况，提供有权访问的普通业务处理入口，不自动补建、恢复或覆盖。无处理权限时说明限制，不借 Agent 扩权。正常初始提交超时仍先回查同次确认，不把结果未知误当历史异常或已知失败。
- **F3 按操作授权：** Agent 与对应普通业务操作采用相同权限，取消通用审核对发团写权限的一刀切要求。能提交初始账款不代表能创建客源/资源；保留本人会话、组织隔离及每次确认的实时校验，按实际权限集合判断，不硬编码角色名。

代码基线：现有初始应收生成使用客源行锁及事务；存在部分有效账款时普通生成服务可能补建缺失路径。后者不能带入本期 Agent，必须在同一确认事务中检查既有账款，不符合 F2 时不得进入补建分支。普通初始生成路由当前要求 `/departure`，新增客源/资源要求 `departure:write`。

确认记录：grilling Q12–Q14 用户答复“同意推荐”，形成 F1–F3。业务选择已明确，事务接入与权限测试仍须完成。

## 10. 已确认的交互规则

确认日期：2026-09-07。用户对讨论轮中的六项推荐统一答复“同意推荐”。以下以该轮推荐为准，替代 v0.1 待决建议。

| 编号 | 主题 | 已确认规则 |
|---|---|---|
| Q1 | 未提及信息 | 先形成审核稿，儿童人数、优惠、调整等未提供内容明确标为缺失；集中确认一次适用项，允许用户明确选择无儿童、无调整、无优惠。Agent 不静默归零，不拆成多轮逐字段追问。 |
| Q2 | 模式切换 | 字段含义变化时要求重新确认，不自动迁移金额。分拆模式的客户已收定金不能直接变成全部代收模式的我方代收定金。同次编辑保留各模式草稿，切回可找回并核对；正式保存仅采用当前模式有效值。切为无优惠立即停止扣减，旧金额只留编辑草稿。 |
| Q3 | 多笔同类调整 | 先区分不同费用与重复材料。确认是不同费用后展示逐笔依据及合计，正式录入一条固定类别调整；无法判断重复时先询问，不直接相加、不丢明细。 |
| Q4 | 名单不完整 | 允许先建客源单并录入完整名单。明确显示计费人数、本次录入人数和未完成项；缺姓名候选不写入，保留待补充内容。不能因此自动改变计费人数，也不让名单不齐持续阻止整单创建。 |
| Q5 | 非现有字段 | 首期不因材料包含年龄、证件或电话类型而新增业务字段，不强制确认无关信息。保留原材料依据；需要写备注时明确告知用户，证件等敏感内容不自动复制进备注。 |
| Q6 | 精度与币种 | 先明确最终人民币金额。Agent 不自行选择汇率或截断金额；可提出换算或舍入建议，但须展示依据，经用户确认后才参与计算。 |

Q4 的确认单元是“客源单＋本次完整且明确纳入的名单”，未完成候选保留在协作中；保留待补充不代表已写入正式名单。Q2 的草稿恢复不代表认可新业务含义，恢复后仍需核对。Q6 尚未经确认的换算只显示为建议，不进入权威结算结果。

六项产品选择已收口。第9节账款异常与授权已由 F1–F3 确认；下一步核对第12节技术差距，不把本次确认扩大解释为生产实现就绪。

## 11. 可复核验收例子

| 输入/操作 | 预期 |
|---|---|
| 8成人×6800，2儿童×4200，单房差+600，住宿扣减−400，整单优惠2000 | B=62800，A=200，S=61000 |
| 上例改为无优惠 | S=63000，停止扣减，旧优惠只保留编辑草稿（Q2）；不能仍扣2000 |
