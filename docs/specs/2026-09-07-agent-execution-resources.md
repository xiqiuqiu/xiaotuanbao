# 执行资源业务功能规格（讨论稿）

关联交互 PRD：[#483](https://github.com/xiqiuqiu/xiaotuanbao/issues/483)。版本 v0.13，2026-09-07。当前 R1–R25 已确认，已补齐现有字段、状态及初始应付的代码基线；协作持久化、版本冲突和权限集成仍待技术设计验证，不视为全部实现已就绪。

## 已确认规则

### R1：沿用现有字段，只要求总价

用户明确：此前已与客户沟通，资源可以直接填写总价，不要求费用明细。本期沿用资源种类、供应商、项目名称、总金额和备注，以及既有业务归属；不新增数量、单价、容量等结构化字段。

有明细需求时推荐填写备注。材料已有明细可作为备注建议并保留来源，但不得把数量、单价及明细计算设为创建资源的额外必填步骤。原型中的房间数、座位数与计划人数硬校验不是已确认业务规则；按 R5 提醒，不作为费用录入硬阻断。

### R2：按材料中的服务范围确定归属

明确某日的服务匹配对应行程段；明确全程的服务归为发团级资源。日期多义、缺少对应段或范围不明确时先核实，不因当前打开某一天而默认挂到该日。

日期用于阅读分组，不因按日展示而拆分供应商整体报价。覆盖部分日期的整体服务按 R4 归属。

### R3：按独立服务与独立约定金额形成资源项

材料中可以明确识别的服务及其独立约定金额构成候选资源项；同供应商不强制合并，同一天不强制共同确认。连续多晚酒店只给整体报价时保持一项，不自动均摊到每晚。

分别给出金额的酒店、接送、用餐可分别成项和确认。不得凭空拆价；服务范围和归属仍遵循 R2。

### R4：跨日整体费用的归属

仅覆盖部分日期的整体费用作为一条发团级资源，备注写清服务日期。不强塞进某一天、不拆价；明确单日费用仍挂对应行程段。

### R5：执行信息冲突只提醒

有明确材料依据时提示容量等执行信息冲突，不强制阻止费用资源录入；不得猜测资源必须服务全部游客。保存成功仅表示费用记录已保存，不表示运力已满足或安排已经核实。不新增容量字段，也不要求用户补齐所有执行明细。

### R6：总价可以由明确明细提出计算候选

材料未给总价但数量、单价、计价单位及适用范围明确时，可提出计算候选并展示依据，经用户确认后作为总价。缺晚数、单位等必要条件先补问；既无总价也无法可靠计算时保留待补充，不用0元代替。计算过程是材料依据，不要求扩展正式字段。

### R7：供应商未匹配时保留候选

保留资源候选，提示选择已有供应商或先通过普通入口维护供应商档案；不自动创建、不随意匹配。其他供应商明确的资源可以先确认。维护完成后回到原候选重新匹配、校验并继续处理。

### R8：最终约定总价优先于明细计算

材料明确标注最终结算或最终约定总价时采用该总价，同时展示与明细计算的差异说明。仅有矛盾金额而无明确最终价时询问用户，不擅自采用某个金额或用计算值覆盖约定价。

### R9：重复材料与变更分开处理

先判断是重复材料还是明确变更，无法确定则澄清。未确认候选展示差异后修订同一项，不重复新增；已写入资源提示关联正式记录和变更意图，不静默修改金额。本期正式记录修改通过现有业务编辑入口处理，相关材料保留在协作中。

### R10：不以0元代替未知费用或免费服务

沿用现有资源总金额必须大于0的规则。金额未确定时保留待补充候选；明确免费、已包含在其他费用中的服务记录在相关备注或材料中，不生成0元费用行，也不要求为其虚构金额。

### R11：创建成功后选择继续提交应付

仅在资源创建成功结果中提供“继续提交应付”。默认列出本次已成功录入且尚未提交应付的资源，允许用户选择；未确认或写入失败的资源不参与。应付另行审核，准备提案不等于正式提交。

应付提交失败不回滚已成功创建的资源，不重新创建资源。用户可以暂不处理，之后从业务页面提交。准备及确认应付时重新核对正式资源、权限与已有账款，避免因状态变化重复提交。

### R12：资源名称可从材料整理

审核时必须有可理解的资源名称。Agent 可根据材料整理名称，例如“4月2日住宿”，随该资源一并由用户确认；不得补入未提供的房型或服务标准，不要求用户为已有足够信息的材料重复命名。现有接口允许空名称不代表新审核可以省略名称。

### R13：多服务整体报价按业务含义归类

整体报价不拆价。旅行社供应商整体承接酒店、接送、用餐等服务时，可提出“拼出”候选，备注列明服务内容；无法明确归类时先询问，不把所有打包报价自动归为拼出。选定类别必须与供应商类别匹配。

### R14：资源种类变化时重新校验供应商

未确认资源更改种类后重新校验原供应商：符合新类别则保留，不符合则提示重新选择或通过普通入口维护档案，其他候选信息保留。不得自动修改供应商类别或将资源改为“其他”以绕过校验。重新匹配后确认前再次执行服务端校验。

### R15：新材料与人工修订冲突

保留人工修订值，在对应字段展示新材料建议值及来源，用户选择保留或采用。冲突未解决前仅阻止该事项确认，不阻止其他独立事项；不要求重填整条资源。

### R16：正在编辑时延后展示新结果

用户编辑期间新材料识别完成，不刷新或打断正在编辑的内容，提示“有新的材料结果待核对”。保存或取消本次编辑后再展示差异。保存编辑不代表接受新材料，也不代表确认写入。

### R17：一个事项保留连续修改记录

事项列表始终保留同一条事项，默认展示最新待审内容；右侧可展开修改记录，查看改动前后、来源与修改者。旧版本只读，不为每次修订新增事项卡，不提供一键恢复整份旧版本，避免同时恢复已失效信息。此为用户交互约定，具体修订存储方式仍由技术方案落实。

### R18：未人工修改的字段更新候选

新材料明确提供最终或替代值，且该字段未经人工修改时，可更新同一事项的待审候选，突出展示前后值与来源。不另设“接受更新”步骤，正式写入仍须最终审核确认。新旧材料互相矛盾且无法确定有效值时保留冲突，不自动选值。正在编辑时仍遵循 R16，延后展示差异，不覆盖输入。

### R19：相关补充材料未处理完时暂停该项确认

用户针对该事项补充材料后，解析尚未完成时暂时阻止该事项确认，提示“正在处理补充材料，请核对更新后再确认”；其他独立事项不受影响。解析失败可重试、改用文字补充，或由用户明确选择本次不采用该材料后继续审核原内容，不静默忽略材料。

### R20：已解决冲突不因重复材料重新打开

用户已明确选择保留或采用某个值后，重复上传或重新识别相同业务内容，不重复提醒、不重新阻止确认。保留已核对的处理记录与所选值。只有出现新的实质信息，例如新的最终报价，才重新提出核对；文件名变化、重复上传或识别重跑本身不是重新打开冲突的依据。记录针对已核对的具体冲突，不把一次选择视为自动拒绝所有未来材料。

### R21：结果未知时先核对，不判定创建失败

确认请求超时或连接中断而结果尚不明确时，显示“正在核对提交结果”，自动查询服务端结果。持续无法确认时提供“重新查询结果”，暂不允许修改或重新创建该项；其他独立事项仍可处理。用户离开后再进入可继续恢复，不以浏览器超时或流关闭推断业务失败。

### R22：按失败原因提供继续入口

同一结果区逐项显示成功和失败。成功项保持已写入，不要求重复审核；业务条件失效等失败明确说明原因并提供“修改后重新确认”。仅内容和业务条件均未变化的技术失败提供直接重试，重试仍须核对实际结果及实时业务条件。不提供混合处理不同失败原因的“全部重试”。结果未知按 R21 处理，不归入可直接重试的已知失败。

### R23：提交开始后不提供撤销提交

提交前允许取消审核或修改；进入提交后不提供“撤销提交”，允许离开页面并回来查看结果。关闭窗口不承诺阻止后台写入。提交成功后的业务变更走正式业务入口；已确定失败后的修改与重试按 R22 处理，不能把隐藏界面当成撤销业务效果。

### R24：单项自身失败不停止其他已选独立项目

多选提交时，若失败仅涉及该项自身条件，例如接送供应商停用，继续提交其他已选中的独立项目，最终逐项展示真实结果。不得扩大到未选择项目，其他项目仍须通过各自实时校验。共同条件失效时不得绕过业务或权限校验，未执行展示与恢复遵循 R25。

### R25：共同条件失效后显式继续剩余项目

发团关闭、写入权限撤销等共同条件失效时，停止尚未执行的项目，显示“未执行”及具体原因；保留已成功结果，不将其回滚或重新提交。条件恢复后由用户点击“继续提交剩余项目”，系统重新校验；内容或版本已变化的项目须先重新审核。不得在后台自动恢复提交，不扩大原有选择范围。已提交但结果未知的项目仍按 R21 核对，不冒充尚未执行项。

## 字段与编辑约定

下表承接 R1–R14；现有接口是实现证据，不因接口宽松而放宽已确认的审核条件。待补充候选可保存不完整内容，正式确认须满足全部必填和有效性条件。

| 字段 | 来源及正式确认条件 | 编辑与联动 |
|---|---|---|
| 业务归属 | 当前发团确定对象边界；材料确定对应行程段或发团级，必填；单日/跨日按 R2/R4 | 不确定时核实；不得把当前浏览日期当成材料事实；正式写入分别对应段资源或发团级资源 |
| 资源种类 `resourceKind` | 必选；新增沿用当前表单八类：用车、酒店、导游、拼出、门票、用餐、保险、其他 | 用户可修订；变化时按 R14 重验供应商；不得用其他绕过类别匹配 |
| 供应商 `supplierId` | 必选；从材料识别并匹配同组织、有效且类别包含所选资源种类的供应商 | 名称相似不代表匹配成功；缺档按 R7；拼出也使用供应商，不新增历史合作伙伴 `partnerId` 写入路径 |
| 项目名称 `title` | 非空、非纯空白；材料原名或有依据的整理名称，按 R12 | 用户可编辑；整理后的名称随资源一并确认，不虚构服务标准 |
| 总金额 `amountCents` | 人民币分的正整数；界面以元显示，材料约定值或 R6 的明确计算候选 | 可修订并保留依据；未知与0均不能正式提交；矛盾总价按 R8，不静默取值或舍入 |
| 备注 `notes` | 可空；服务日期、材料中的明细、服务说明等，非金额必填替代物 | 可编辑/清空；不强制用户提供明细；删除备注不删除原始材料证据 |

供应商类别全集和历史资源枚举还包含景区、购物店、演出，不能据此扩展新增入口；历史记录仍可识别、回看，正式记录编辑沿用普通业务入口。拼出对应供应商类别的显示名称为“旅行社”。

每项独立编辑：保存仅更新待审核候选，取消恢复本次编辑前内容；均不提前写正式资源。人工修订与新材料冲突时展示差异，按 R9 核实后更新同一候选，不覆盖已确认版本。类别、供应商和金额等字段修订后重新校验该项。确认时以用户实际审核的版本为准，发生变化须重新审核。

## 状态与初始应付约束

| 状态或动作 | 本期行为与现有基线 |
|---|---|
| 发团已关闭 | 现有 `assertMutable` 拒绝编辑；候选保留并说明原因，不自动改变发团状态 |
| 发团已结清 | `assertAllowsNewObligation` 拒绝新增账款；资源编辑与新增账款是不同校验，不能由资源保存成功推导应付可提交 |
| 资源创建成功 | 保存正式资源 ID 与归属类型，结果可回看；R11 的下一步仅使用本次成功记录，不重新识别材料生成另一份资源 |
| 应付准备及确认 | 以正式资源的供应商、金额、来源类型/ID为依据，展示后独立确认；当前生成服务采用发团结束日期作为到期日，不额外引入账期编辑流程 |
| 已有未作废应付 | 当前生成服务阻止重复生成，其中包括 `cancelledAt` 非空但 `voidedAt` 为空的账款；显示真实关联状态，不把取消当成从未提交 |
| 仅有作废历史 | 当前生成去重查询排除了 `voidedAt` 非空记录；这不构成本期 Agent 自动重建授权。R11 仅承接本次新增资源，历史账款重建不纳入该入口 |
| 多项应付部分失败 | 已成功资源和应付保留，逐项显示成功、失败或已存在；重试先查询实际状态，只重试仍未完成且可提交的选中项 |
| 正式资源后续变更 | 本期转普通业务编辑入口；现有财务状态会因取消、付款/核销历史或结清等锁定金额，Agent 不绕过锁定或同步改账 |

当前单资源生成应付使用事务及资源行锁，并在锁内重读资源、检查发团状态和已有未作废账款。这是可复用的业务保护，不等同于已经实现协作事项的幂等确认或刷新恢复。

## 已核实的复用点与实现差距

| 项目 | 已有能力 | 新交互接入要求 / 尚未验证 |
|---|---|---|
| 资源录入 | 段资源、发团级资源服务；正整数金额、供应商组织/状态/类别校验 | 审核须补足非空名称和新增八类约束；DTO 的可选供应商/名称及完整枚举不能直接成为审核规则 |
| 批量提交应付 | 段级批量服务逐项处理，保留成功并返回部分失败 | 该入口扫描整段资源，不能直接承接 R11 选中的本次成功子集；需传递并核验明确来源集合，复用单资源生成保护 |
| 已存在的应付 | 服务端重复提交返回冲突；批量过程可能略过已有项 | 协作结果必须列明每个选中项的真实结果和关联记录；“略过”不能显示成本次新建成功 |
| 并发与版本 | 应付生成有资源行锁和事务内重读 | 仍需验证候选版本、用户审核快照与正式资源变更的衔接，不能把行锁当成完整版本控制 |
| 刷新、超时和重复确认 | 当前资源 CRUD DTO 未携带协作事项/证据标识 | 需进一步追踪现有 Agent 执行与持久化链路，明确候选到正式 ID、确认结果和恢复查询的保存位置；未核实前不宣称缺失整个基础设施，也不先造新框架 |
| 权限与组织隔离 | 资源服务查询限定组织并校验供应商 | 技术设计还需逐操作核对路由权限及 Agent 调用权限，确认时重新校验；前端隐藏入口不构成授权 |

| 金额未提供且不能可靠推算 | 保留待补充，不以0元录入 |
| 材料明确免费或包含在其他费用 | 保留相关备注/材料，不创建费用行 |
| 酒店与用餐创建成功，接送未确认 | 后续应付选择仅列本次成功且未提交的酒店、用餐 |

| 应付失败后返回或重试 | 资源不回滚、不重复创建，正确显示应付未完成 |
| 材料仅有酒店、日期和总价 | 提出有依据的资源名称，不虚构房型 |
| 旅行社整体承接多类服务且仅有总价 | 可提出拼出候选，列服务备注并校验供应商类别，不拆价 |
| 酒店候选改为用餐，供应商不支持用餐 | 保留其他内容，要求重新匹配，不自动扩供应商类别 |
| 已关闭发团尝试录入资源 | 拒绝编辑，候选保留并说明原因 |
| 已结清发团的资源结果选择提交应付 | 不允许新增应付，不自动改发团状态 |
| 整段另有不属于本次成功结果的未提交资源 | 不进入本次应付确认和写入范围 |
| 选中资源被其他人先提交应付 | 回查关联结果，显示已存在，不重复生成或伪报本次新建 |
| 请求超时或刷新后再次打开 | 先恢复并核对正式结果，状态不明时不盲目重建资源或应付 |
| 审核后供应商失效或类别改变 | 确认失败保留候选，提示重新匹配；其他独立项不回滚 |
| 审核版本与待执行版本不同 | 不执行旧确认，展示差异并重新审核 |
