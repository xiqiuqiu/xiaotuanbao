# 团内增收记录取代团上收入台账（第一期）

> Spec for agent implementation. Triage: intended `ready-for-agent`.  
> Domain: ADR-0036、`CONTEXT.md`（Departure Income Record / Company Income / Additional Income Net）。  
> UI prototype (throwaway): branch `0729增收记录开发`, `?tab=incomeRecords&variant=A`。  
> Product draft: `ider/团内增收记录功能_PRD.md`。

## Problem Statement

地接社在发团执行中，除团款外还会产生购物店返利、车销收入、自费项目返利等附加收入，并常需向导游支付提成。系统现有的**团上收入台账**只能登记自由标题 + 金额，缺少类型、合作方、导游提成与结算跟进标记；计调与财务只能在线下表格或聊天里维护，无法在发团内核对单团增收净收益。

## Solution

用**团内增收记录**整表替换团上收入台账（不并存）。发团详情提供「增收记录」页签（方案 A：顶部合计 + 筛选表 + 抽屉录入），支持四种增收类型、导游提成、公司增收派生、收入/提成台账状态与单团**增收净收益**汇总；概览与发团运营表同步新口径。第一期状态不进应收/应付/核销，不改当前毛利公式。

## User Stories

1. As a 计调, I want 在发团详情看到「增收记录」页签（位于执行安排之后）, so that 执行过程中能就地登记团款外收入。
2. As a 计调, I want 新增购物店返利记录, so that 门店应返金额有据可查。
3. As a 计调, I want 新增车销收入记录且可不选合作方, so that 车上销售也能入账。
4. As a 计调, I want 新增自费项目返利记录, so that 游船/演出等返利可登记。
5. As a 计调, I want 新增其他增收记录, so that 无法归类的临时收益也有台账。
6. As a 计调, I want 录入项目名称（必填、≤50 字）, so that 列表能识别这笔增收。
7. As a 计调, I want 从供应商中选择合作方（可空）, so that 返利对手方可复用供应商名录。
8. As a 计调, I want 在购物店返利/自费返利时看到「建议填写合作方」提示但不被强制, so that 尚未建档供应商时仍可先记金额。
9. As a 计调, I want 填写发生日期（默认当天、可改）, so that 增收可按发生日核对。
10. As a 计调, I want 填写增收金额（≥0、两位小数）, so that 台账金额准确。
11. As a 计调, I want 按增收类型看到对应的增收金额字段提示, so that 不会填错口径（应返/销售收入/项目返利/实际增收）。
12. As a 计调, I want 选择导游（默认本团执行班组导游，可改选导游类供应商，可空）, so that 提成归属清晰。
13. As a 计调, I want 填写导游提成（默认 0、不得大于增收金额）, so that 应付导游部分被记录。
14. As a 计调, I want 系统自动显示公司增收（增收金额−导游提成、只读）, so that 不用手算公司所得。
15. As a 计调, I want 设置收入状态（未收/已收，默认未收）, so that 知道返利是否到账。
16. As a 计调, I want 设置提成状态（未付/已付，默认未付）, so that 知道导游提成是否已付。
17. As a 计调, I want 填写备注（≤200 字、可空）, so that 人数/商品/结算约定可补充。
18. As a 计调, I want 编辑已有增收记录, so that 录错可改。
19. As a 计调, I want 删除未结算记录（收入未收且提成未付）, so that 错误登记可清掉。
20. As a 计调, I want 删除已收或已付记录时二次确认, so that 有结算痕迹的行不会误删。
21. As a 计调 or 财务, I want 在列表上「标记已收」, so that 不用进抽屉也能推进收入状态。
22. As a 计调 or 财务, I want 在列表上「标记已付」（提成＞0 且未付时）, so that 可推进提成状态。
23. As a 用户, I want 看到综合状态（待结算/待付提成/待收增收/已结算）由收入与提成状态派生, so that 一眼知道跟进阶段。
24. As a 用户, I want 顶部看到增收金额合计、导游提成合计、公司增收合计, so that 与列表有效记录一致。
25. As a 用户, I want 按增收类型筛选, so that 只看某一类增收。
26. As a 用户, I want 按综合结算状态筛选, so that 优先处理未结清项。
27. As a 用户, I want 按项目名称/备注/合作方关键词搜索, so that 快速定位记录。
28. As a 用户, I want 概览经营补充看到「增收净收益」卡（= 公司增收合计）, so that 扫一眼知道团净增收。
29. As a 用户, I want 概览不再出现「其他收入」卡与团上收入台账录入区, so that 不会与增收记录双入口混淆。
30. As a 用户, I want 增收净收益不计入结算应收、团款收款进度与当前毛利主指标, so that 既有毛利口径不被打乱。
31. As a 计调, I want 发团运营表在有数据时展示「增收记录」分区（类型、项目、合作方、增收金额、导游提成、公司增收、综合状态）, so that 导出总账本含增收事实。
32. As a 计调, I want 运营表该分区合计显示增收净收益, so that 与概览口径一致。
33. As a 计调, I want 无增收数据时运营表省略该分区, so that 空团导出不冗余。
34. As an 有发团编辑权限的用户, I want 能新增/编辑/删除/标记增收记录, so that 权限与现有发团写入一致。
35. As a 无发团编辑权限或发团只读（如已关闭/金额锁定）的用户, I want 只能查看增收记录, so that 不会误改。
36. As a 用户, I want 「标记已收/已付」不生成应收单或应付单、不要求登记流水, so that 第一期保持轻量台账。
37. As a 用户, I want 增收记录不计入资源成本与应付合计, so that 成本侧不被污染。
38. As an 管理员或运维, I want 历史团上收入行一次性迁为「其他增收」（项目名称=原标题，提成 0，未收/未付）, so that 旧数据不丢且口径统一。
39. As a 用户, I want 迁移后无法再使用旧团上收入 API/UI, so that 只有一套台账。
40. As a 用户, I want 有增收记录时发团不能被 purge 删除（文案改为增收相关）, so that 有业务事实的空壳规则与现网一致。
41. As a 开发者, I want 权限矩阵与 departure e2e 覆盖新路由与概览/运营表口径, so that 替换不回退主路径。
42. As a 产品/评审, I want DEV 原型在正式页签落地后移除 throwaway 切换条与 A/B/C 变体, so that 生产不残留原型入口。

## Implementation Decisions

- **替换范围**：团内增收记录取代 Ground Income Ledger；不并存。权威：ADR-0036。
- **主模块**：Departure 上下文内扩展（与现 Ground Income 服务 / 读模型 / 运营表同一 seam），不新开独立佣金或销售子系统。
- **数据模型**：以新实体（或等价演进后的表）承载：类型枚举（购物店返利 / 车销收入 / 自费项目返利 / 其他增收）、项目名称、可选合作方 SupplierId、发生日期、增收金额（分）、可选导游 SupplierId、导游提成（分）、收入状态、提成状态、备注、时间戳。公司增收与综合状态为派生，不单独落可编辑字段。
- **迁移**：发布时将既有 `ground_incomes` 行迁为类型「其他增收」；项目名称←title，增收金额←amountCents，合作方/导游空，提成 0，收入未收、提成未付；随后删除旧表/旧 API。
- **API**：发团子资源 CRUD + 可选快捷标记已收/已付；列表可带类型与综合状态筛选及关键词。菜单能力沿用 `/departure` 读、`departure:write` 写；变更后更新权限矩阵快照。
- **校验**：增收金额 ≥ 0；导游提成 ≥ 0 且 ≤ 增收金额；项目名称必填 ≤50；备注 ≤200；合作方/导游可空；导游若填须为导游类供应商（或本团班组导游）。
- **可变性**：沿用 Departure 可变性与 settled 等现有拦截（与旧团上收入一致）；无写权限或 mutationLocked 时前端只读。
- **概览**：原「其他收入」合计改为增收净收益口径（Σ 公司增收）；文案与说明同步；移除概览内台账 CRUD。
- **运营表**：预览与 Excel 分区「增收记录」及合计「增收净收益」。
- **Purge**：以是否存在增收记录为准；错误文案改为增收相关。
- **Web UI**：正式启用 `incomeRecords` 页签（去掉 DEV-only 门闩）；布局对齐原型方案 A——顶部三合计、类型/综合状态/关键词筛选、表格、抽屉表单；行操作含编辑、删除、标记已收、标记已付。
- **共享类型**：在 shared 包提供增收记录 DTO/摘要与概览、运营表字段；退役 Ground Income / otherIncome 产品语义。
- **原型清理**：落地后删除 throwaway 变体与切换条对正式页的依赖（可另 PR）。

## Testing Decisions

- **只测外部行为**：通过 HTTP API 与必要的 UI/读模型断言验证用户可观察结果；不测私有实现细节。
- **主缝**：`departure` API e2e 中现有团上收入链路——演进为增收记录 CRUD → 概览增收净收益 → purge 拦截 → 运营表增收分区/合计。不新开平行 e2e 套件。
- **辅助**：读模型单元（合计映射）；Web 概览卡文案/金额；运营表分区渲染；tab 可见性（正式环境恒显）；写权限契约与权限矩阵快照。
- **先验**：沿用现网 ground-income 相关断言位置与模式，替换期望值与字段名即可。

## Out of Scope

- 游客实际消费总额、返利比例、按人数/销售额自动计算。
- 车销商品数量、单价、库存。
- 多导游提成拆分。
- 部分收款/部分付款。
- 自动生成应收单、应付单；接入收支流水与核销。
- 审批流、跨团对账单、供应商返利协议管理。
- 将增收净收益并入当前毛利主指标公式。
- 计调/财务按钮级权限拆分（第一期沿用发团编辑）。
- 独立「行程日报」或第二套销售工作台。

## Further Notes

- 原型结论：方案 A；分支 `0729增收记录开发` / PR #233。
- 详情 Tab 产品文案「增收记录」；执行安排仍合并行程段+资源安排（与现网一致）。
- 「公司增收」（行）与「增收净收益」（汇总）同一公式、两处文案。
- 综合状态派生：未收+未付→待结算；已收+未付→待付提成；未收+已付→待收增收；已收+已付→已结算。
- **Seams（已确认）**：主缝 = departure e2e 团上收入链路演进；辅助 = 读模型合计、Web 页签/概览、权限矩阵。
