## Problem Statement

地接社按月与发客合作方（Partner）对账：客户实际做法是每月 10 号导出上月与某合作方相关的全部发团记录核对资金，对方签章确认后再收款核销。当前系统内该流程完全断裂——Partner 详情的「合作团单」「往来账款」两个 Tab 仍是占位（`SupplierComingSoonPanel`），对外对账单据靠线下 Excel 模板「月度往来账确认单」手工整理，费时且易错。

## Solution

在 Partner 详情实装两个分层 Tab，并交付合作伙伴维度按时间段导出《往来账确认单》：

- **合作团单 Tab ＝ 业务事实层**（行 = 客源单）：回答「这家发了哪些团、金额怎么构成」，并作为确认单导出的唯一入口。
- **往来账款 Tab ＝ 财务账款层**（行 = 收付款节点）：回答「这家欠我 / 我欠这家多少、收付到哪一步」。
- **《往来账确认单》**：按对账周期（所属发团出团日期区间）面向单一 Partner 即时生成的对外签章单据，只含业务事实与收款拆分，不含核销进度。

两 Tab 数据面天然错开（交集仅「客户补款」一个金额且语义错开：约定构成 vs 收款进度；游客代收节点 counterparty=guest，不属于该 Partner 账款），用动线衔接月度对账流程：合作团单筛时间段导出确认单 → 对方签回 → 往来账款收款核销。

原设想的「发团维度合作伙伴结算表」经 #114 决议**取消**：对外对账统一走周期版确认单这一个出口，单团结算是周期特例（周期设为该团出团日）。

## User Stories

### 合作团单 Tab

1. 作为计调，我希望在 Partner 详情看到该合作方全部客源单（跨发团），按出团日期筛选，以便了解合作规模与金额构成。
2. 作为计调，我希望列表上方汇总卡跟随筛选（所见即所导），以便导出前先核对总数。
3. 作为计调，我希望从团单编号直接跳进发团详情，以便核对单团细节。
4. 作为计调，我希望在此 Tab 一键导出《往来账确认单》，预览后下载发给对方。

### 往来账款 Tab

5. 作为财务/计调，我希望在 Partner 详情分应收、应付两个子区查看与该合作方的全部账款节点，以便回答「他欠我 / 我欠他多少」。
6. 作为财务，我希望应收侧汇总拆显「客户补款 / 其他应收」，以便与同周期确认单的「客户已收押金」合计严格对上。
7. 作为财务，我希望按所属发团出团日期筛账款（与确认单周期同口径），对完账直接在 Tab 内登记收款、匹配流水。
8. 作为财务，我希望保留到期日筛选做催收用途。

### 确认单导出

9. 作为计调，我希望选定对账周期后即时生成确认单（xlsx，A4 横向一页宽），格式贴近对方已习惯的月度模板，便于对方签章确认。
10. 作为计调，我希望确认单上的单价拆成人/儿童两列，让对方逐行可复算。
11. 作为财务，我希望确认单只含业务约定金额与收款拆分、不含我方核销进度，避免把内部财务处置暴露给对方。

## Implementation Decisions

### 分层原则（#109）

| | 合作团单 Tab | 往来账款 Tab |
| --- | --- | --- |
| 层 | 业务事实层 | 财务账款层 |
| 行 | 客源单 | 收付款节点 |
| 回答 | 发了哪些团、金额构成 | 欠多少、收付到哪一步 |
| 列上有意不放 | 应收状态、已收/未收 | 人数、单价、优惠 |

游客代收路径生成的应收节点往来对象是客源单（`counterpartyType=guest`），**不出现**在该 Partner 的往来账款 Tab 中。

### 权限

沿 Partner Epic 1：企业管理员、计调可访问 `/partner` 及详情子路由；财务不可见。本 Epic 新增的 Partner 维度接口一律 `@RequireMenu('/partner')`。财务人员的账款操作主路径仍是全局应收/应付页（不受影响）。

### 合作团单 Tab（#110）

#### 方向与空态

第一版**只做客户方向**（行 = 客源单）。`partnerKind` 为纯承接方、或该 Partner 暂无客源数据时显示空态文案；拼出方向合作记录不做（见 Out of Scope）。

#### 汇总卡（六项，跟随筛选，所见即所导）

客源单数｜总人数｜原始团款合计｜优惠合计｜结算金额合计｜游客代收合计

系统内用 CONTEXT.md 规范名；客户习惯名仅出现在导出物。现有 `SourceOrderListSummary` 缺**原始团款合计**（`totalGrossReceivableCents`），需补充。

#### 列集

出团日期｜发团编号＋线路名（链接进发团详情）｜客源单展示名｜成人/儿童｜单价（成人/儿童）｜原始团款｜优惠｜结算金额｜客户已收｜游客代收｜备注

- **有意不放**：应收状态与已收/未收（归往来账款 Tab）；游客代表与联系电话（Tab 日常浏览用不上，仅出现在导出物）。
- 系统无「客源单号」编号字段，Tab 用客源单展示名。

#### 筛选 / 排序 / 分页

- 按**所属发团出团日期**筛选：任意区间＋快捷项（本月/上月/近 3 个月），默认不限时间。
- 默认出团日期倒序；标准分页。

#### 导出确认单入口

- **全系统仅此一个入口**，位于本 Tab 工具栏右上角。
- 交互沿发团运营表模式：抽屉页面预览＋下载 xlsx。
- 对账周期预填当前筛选区间、可改、**必填**；当前筛选为不限时间时须先选区间（确认单标题由周期生成）。

### 往来账款 Tab（#111）

#### 双向组织

两个子区「应收」「应付」，各自复用一次 `PaymentScheduleWorkspace`；数据用 `counterpartyType=partner + counterpartyId` **精确过滤**（不走 keyword 模糊匹配，同名 Partner 不串）。后端列表 API 已支持精确过滤，Workspace 需扩展 props 接线。

#### 汇总卡（每方向三项，跟随列表筛选）

约定合计｜已核销合计｜未结清合计

- 已关闭（`cancelled`）、已作废节点**不计入**。
- 应收侧约定合计拆显构成：「应收合计 X（客户补款 Y ／ 其他应收 Z）」；Y 与同周期确认单「客户已收押金」列合计严格对得上。
- 游客代收不在本 Tab（#109 边界）；确认单「实际应收」中的游客代收段不在此核对。

#### 时间轴

- 新增「**所属发团出团日期**」区间筛选（快捷项同合作团单 Tab），作为与确认单周期同口径的主时间轴。
- 保留到期日筛选做催收用途。
- 手工其他应收按领域定义归属发团（CONTEXT.md），随其所属发团出团日期落入区间。

#### 操作能力与深链

- Tab 内**完整操作**，与全局应收/应付页一致：登记收款/付款、匹配流水、编辑、关闭、调整金额均页内完成；「查看核销」维持跳全局核销页。
- 发团客源 Tab 的「查看应收」深链**维持现状**（发团语境正确），与本 Tab 并行不冲突；本 Tab「关联发团」列链接天然提供反向动线。

### 《往来账确认单》导出（#112 口径 ＋ #113 版式）

#### 数据口径

| 项 | 决议 |
| --- | --- |
| 对账周期 | 所属发团**出团日期**区间（与两 Tab 同口径） |
| 行范围 | 周期内该 Partner **全部客源单**；应收已关闭的客源单照常列入、金额如实显示、**不做标记**（业务事实层单据，财务处置不渗透） |
| 排序 | 明细按出团日期正序 |
| 单价 | 拆「拼入单价（成人）｜拼入单价（儿童）」两列，与成人/儿童人数列对齐；成人×成人价＋儿童×儿童价＝原始应收，逐行可严格复算 |
| 手工应收（其他应收） | **排除**（无客源单载体、无出团日期，属财务账款层）；差值由往来账款 Tab 应收侧拆显解释 |
| 游客代表、联系电话 | **保留**两列（收件方即客人信息原始提供方，且是对方认单的主要锚点）；取值沿 Guest Representative 既有规则，名单空则留空 |
| 客户单号 | **删除**，不新增字段；对方认单靠日期、线路、游客代表 |
| 确认状态 | 第一版**不跟踪**；即时生成当前快照、不存副本、不留导出历史；签回件线下归档 |

#### 对外命名（豁免仅限导出物）

导出物整套沿用客户习惯名，与系统规范名映射（已入 CONTEXT.md「Partner Reconciliation Statement」词条）：

| 导出物（客户习惯名） | 系统规范名 |
| --- | --- |
| 拼入合计 | 原始团款合计 |
| 原始应收 | 原始团款 |
| 实际应收 | 结算金额 |
| 客户已收押金 | 客户补款 |
| 游客代收 | 游客代收（同名） |

系统 UI（含两 Tab）维持规范名。

#### 版式（定稿，样张已评审）

整体沿客户模板骨架，纵向顺序：

1. **标题**：由周期自动生成——同年同月「2026年6月往来账确认单」；同年跨月「2026年6-7月往来账确认单」；跨年「2026年12月-2027年1月往来账确认单」。
2. **抬头单行**：合作方＋对账周期（后注「（按出团日期）」）＋导出时间。
3. **六项汇总两行**：客源单数｜总人数｜拼入合计｜优惠合计｜实际应收｜游客代收。
4. **17 列明细**：序号｜出团日期｜团单编号｜线路/团单名称｜游客代表｜联系电话｜成人｜儿童｜合计｜拼入单价（成人）｜拼入单价（儿童）｜原始应收（拼入合计）｜优惠金额｜实际应收｜客户已收押金｜游客代收｜备注。儿童数为 0 时儿童单价显示「-」。
5. **合计行**：人数三列求和，单价两列留空，金额五列求和。
6. **确认说明**：客户原句（3 个工作日反馈）＋补两条——计算口径公式（实际应收＝原始应收−优惠；游客代收＝实际应收−客户已收押金）、本单不含双方收付款进度声明。
7. **双方签章栏**：左「我方确认（盖章）：出具方全名」右「客户确认（盖章）：合作方全名」，各含确认人/确认日期空线。

打印规格：A4 横向、`fitToWidth` 一页、高度自然分页、分页时重复明细表头、页脚页码；金额列 `¥#,##0.00`。

版式细节以样张脚本 `apps/api/scripts/prototype-reconciliation-statement.ts` 为准（本 PRD 定稿后该脚本移除，渲染逻辑迁入正式 renderer）。

### API

基础路径 `/api`；均需 JWT ＋ `/partner` Menu Permission，`organizationId` 从 JWT 解析。

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/partners/:id/source-orders` | 合作团单列表；query：`departureDateFrom`, `departureDateTo`, `page`, `pageSize`；响应含 `items` ＋ `summary`（六项，跟随筛选） |
| GET | `/partners/:id/receivables` | 应收节点列表（镜像 `GET /departures/:id/receivables`，按 counterparty 锚定）；新增 query：`departureDateFrom`, `departureDateTo` |
| GET | `/partners/:id/payables` | 应付节点列表，同上 |
| GET | `/partners/:id/payment-schedule-summary` | 账款聚合：direction × sourceType 分组的约定/已核销/未结清合计（支撑汇总卡拆显）；query 同列表筛选 |
| GET | `/partners/:id/reconciliation-statement` | 确认单 JSON 快照（抽屉预览）；query：`periodStart`, `periodEnd`（必填） |
| GET | `/partners/:id/reconciliation-statement.xlsx` | 即时生成 xlsx buffer，`Content-Disposition` 附件；query 同上 |

**查询能力扩展**（现状缺口）：

1. 客源单：现仅有按发团查询（`GET /departures/:id/source-orders`）；新增「按 Partner ＋ 出团日期区间」跨发团查询。
2. `SourceOrderListSummary` 补 `totalGrossReceivableCents`（原始团款合计）。
3. 收付款节点列表与聚合：新增按**关联发团出团日期**过滤（手工应收经其归属发团的出团日期落入区间）。
4. 新增按 counterparty 的账款聚合端点（direction × sourceType 分组），已关闭/已作废节点排除。

**错误**：`400` 缺必填周期或区间非法；`403` 无 `/partner` 权限；`404` partner 不存在或不属于当前 Organization。

## Testing Decisions

只测对外可观察行为：HTTP 状态码、响应体字段、权限边界、筛选与汇总计数、导出物结构。

### 主测试接缝

**Partner 维度 HTTP E2E**：

- 财务角色访问各新端点 → 403；跨 org partner → 404。
- 合作团单列表：出团日期区间过滤正确；`summary` 六项在 mixed fixtures 下计数正确且跟随筛选；含已关闭应收的客源单照常列入。
- 账款列表：`counterpartyId` 精确过滤（同名 Partner 不串）；出团日期区间过滤含手工应收（按归属发团）；游客代收节点（counterparty=guest）不出现。
- 账款聚合：约定/已核销/未结清正确；已关闭、已作废节点不计入；应收侧按 sourceType 拆显，客户补款合计与同周期确认单快照「客户已收押金」合计相等。
- 确认单 JSON 快照：周期必填校验；行范围＝周期内全部客源单、出团日期正序；逐行原始应收＝成人×成人价＋儿童×儿童价；游客代收＝实际应收−客户已收押金；其他应收排除；游客代表取名单最早一条、名单空则留空。
- 确认单 xlsx：能生成合法 workbook，标题按周期规则生成，17 列表头与合计行正确（结构断言，不逐像素断版式）。

## Further Notes

- 口径底线（CONTEXT.md 传统）：业务源事实与财务账款不混表；确认单只含业务事实＋收款拆分，不含核销进度。
- 实现顺序建议：客源单跨发团查询＋summary 补字段 → 合作团单 Tab → 账款出团日期过滤＋聚合端点 → 往来账款 Tab → 确认单 service/renderer＋抽屉 → 删样张脚本。
- 权威来源：CONTEXT.md ＋ 闭票决议（#109–#114）＞ 客户模板字面 ＞ 本 PRD 之前的占位描述。
