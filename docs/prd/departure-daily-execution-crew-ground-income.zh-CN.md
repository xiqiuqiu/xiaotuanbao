# PRD：发团按日执行安排、执行班组与团上收入台账

**状态**：已定稿（产品决议冻结 2026-07-28；Issue [#199](https://github.com/xiqiuqiu/xiaotuanbao/issues/199)）  
**Menu Key**：`/departure`（执行安排、概览）；应付侧复用现有资源应付生成；供应商名录复用选司机/导游  
**域词汇**：见根目录 [CONTEXT.md](../../CONTEXT.md)（重点：Departure、Itinerary Segment、Segment Resource、Resource Kind、Execution Arrangement、Departure Operations Sheet、Cost Total、Other Receivable、Departure Financial Summary）  
**决议来源**：客户纸质「行程日报表」对照；2026-07-28 A/B/C 冻结决议及四条边界补钉。修订语境：CONTEXT 中「第一版不做到每日行程明细 / 不引入每日行程实体 / 执行班组不结构化 / Avoid 行程日报」——本 PRD **仍不引入独立行程日报实体**，但 **升级** 执行安排：按日行程段骨架、发团级资源锚点、票型人数、发团级班组、团上收入台账。

---

## Problem Statement

地接日常用纸质「行程日报表」管一团执行：多日线路按天安排酒店与门票，车费/保险/导服按整团统一安排；标题写明司机与导游；另登记车销、签单、特产等团上收入。现系统以跨多日的行程段为成本锚点、段下挂资源，**不做每日行程明细**；司机/导游/车牌无结构化字段（仅备注）；无团上销售收入台账。结果是：计调无法按客户习惯「一天一配」酒店门票与按日拼出，全程费用只能硬塞某段，负责人靠备注难查，车销类收入无处录入，概览也看不到这类其他收入。

## Solution

在 **不新建「行程日报」双轨** 的前提下，升级发团执行与概览：

1. **按日出团～回团日一键生成每日行程段骨架**；酒店、门票、**拼出**等按日挂在对应行程段下。  
2. **发团级资源锚点**：全程用车、保险、导游等可挂发团（不强制进某一日段）；资源种类与生成应付规则 **与段资源同一套**。  
3. **票型人数**：每日（段）可录全/半/学/免；与客源单人数合计 **校验并醒目提示**（默认可保存）。  
4. **发团级执行班组**：司机必须选 **用车** 类供应商，导游必须选 **导游** 类供应商，车牌为自由文本；与成本资源 **完全分离**，选人不生成应付。  
5. **团上收入台账**：自由标题 + 金额，可录入与列表管理；**不**自动生成其他应收、**不**用流水推导；概览增加独立 **「其他收入」** 卡，金额 = 台账合计。团上收入 ≠ 购物店类段资源应付。

## Testing Seam（建议确认）

**单一主 seam：发团执行安排编排（Departure execution arrangement orchestration）。**

覆盖：按日段生成与维护、按日段资源与按日拼出、发团级资源 CRUD 与应付生成、票型人数校验提示、发团班组字段、团上收入台账 CRUD、概览其他收入口径。不新开平行「日报引擎」或独立佣金/销售子系统。

> 实现前若开发希望把「团上收入台账」拆为第二 seam，须产品同意；默认仍并入主 seam。

## User Stories

1. As a 计调, I want 按发团出团日与回团日一键生成每日行程段骨架, so that 不必手工建十个空段。
2. As a 计调, I want 生成后仍可增删改某日行程段, so that 实际行程变更可调整。
3. As a 计调, I want 在某一日行程段下添加酒店与门票资源, so that 按日配房配票与纸质习惯一致。
4. As a 计调, I want 在某一日行程段下添加拼出资源, so that 按日拼出也能跟日报节奏对齐。
5. As a 计调, I want 全程用车、保险、导游等费用挂在发团级资源上, so that 不必硬塞进某一天。
6. As a 计调, I want 发团级资源使用与段资源相同的资源种类与供应商规则, so that 学习成本与应付规则一致。
7. As a 财务, I want 对发团级资源显式生成应付, so that 全程成本进入付款跟进。
8. As a 计调, I want 在每日行程段录入全、半、学、免人数, so that 当日票务与人头有据可查。
9. As a 计调, I want 当票型人数合计与客源单人数合计不一致时看到醒目提示, so that 能发现漏录或口径偏差。
10. As a 计调, I want 票型不一致时仍可保存（带提示）, so that 现场微调人数时不被硬拦。
11. As a 计调, I want 在发团上从用车类供应商中选择司机, so that 负责人可结构化查询。
12. As a 计调, I want 在发团上从导游类供应商中选择导游, so that 带团导游清晰可查。
13. As a 计调, I want 填写车牌自由文本, so that 车辆信息可记录且不依赖供应商档案新字段。
14. As a 计调, I want 选择司机或导游时不自动生成应付, so that 班组指派与成本资源解耦。
15. As a 计调, I want 发团运营表或详情能展示司机、导游与车牌, so that 导出/核对时与纸质标题信息对齐。
16. As a 计调, I want 录入团上收入行（自由标题与金额）, so that 车销、签单、特产等有台账。
17. As a 计调, I want 查看、编辑、删除本团团上收入行, so that 可管理登记错误。
18. As a 计调或财务, I want 发团概览看到「其他收入」卡且等于台账合计, so that 不必点进列表才知道总额。
19. As a 计调或财务, I want 其他收入不计入客源结算应收进度, so that 团款进度不被车销扭曲。
20. As a 计调, I want 系统不把团上收入当成购物店资源应付, so that 成本与团上销售收入不混。
21. As a 计调, I want 不进入独立「行程日报」菜单或实体, so that 仍在执行安排内完成配资源。
22. As a 计调, I want 常用路线/模板生成发团后仍可用一键按日铺段, so that 从模板来的团也能对齐按日习惯。
23. As a 计调, I want 发团日期变更时对已有每日段与票型数据有明确处理策略（提示重生成或保留）, so that 改期不静默丢数据。
24. As an agent/developer, I want CONTEXT/ADR 同步「发团级资源、班组、团上收入、按日段」规范名, so that 后续实现不与旧「第一版不做」表述冲突。
25. As a 财务, I want 本迭代团上收入不自动生成其他应收、也不强制登记流水, so that 先闭环台账与概览展示。

## Implementation Decisions

- **权威输入**：本 PRD；客户纸质行程日报表场景；CONTEXT 既有 Departure / Itinerary Segment / Segment Resource 词汇。实现期应新增或修订 ADR（发团级资源锚点、班组、团上收入、按日段生成），并更新 CONTEXT 中「第一版不做每日行程 / 班组仅备注 / Avoid 行程日报」等过时表述——**Avoid 的是独立日报实体，不是按日段能力**。
- **单一主 seam**：发团执行安排编排（见上）。
- **按日行程段**：由发团 `startDate`～`endDate`（或产品约定的出团/回团字段）生成一日一段；段名/目的地可空或占位，计调再填。不引入 `DailyReport` 实体。
- **按日资源与拼出**：段内 Segment Resource 规则不变；拼出与酒店/门票一样按日挂段。
- **发团级资源**：新锚点（资源行归属 Departure，而非仅 Itinerary Segment）。Resource Kind、供应商类别校验、生成应付、finance-touched / 作废重开等与段资源同规则。计入 Cost Total（成本合计）与付款进度分母，与段资源一并汇总。
- **票型人数**：每段（日）存全/半/学/免非负整数；校验对象为各段合计（或产品选定的「执行人头」口径）与本团客源单成人+儿童（及既有人数口径）合计；不一致 → 醒目提示，**允许保存**。
- **执行班组（发团级）**：`driverSupplierId`（供应商类别须含用车）、`guideSupplierId`（类别须含导游）、`vehiclePlate`（自由文本，可空策略由实现定默认：建议可空）、`contactPhone`（联系电话，自由文本，可空）。不写供应商档案车牌字段。与 Segment Resource 无自动联动。
- **团上收入**：发团下多行 `{ title, amountCents, … }`；无品类枚举。概览 `其他收入 = Σ 台账金额`。不生成 Payment Schedule，不要求 Cash Flow。
- **概览**：在 Departure Financial Summary / overviewStats 增加其他收入展示；不并入结算应收或团款收款进度。
- **运营表**：司机/导游/车牌纳入发团头或班组区展示；团上收入是否进运营表导出本迭代建议 **列入**（有则分区展示），若排期紧可标为同 PR 跟随项。
- **历史数据**：已有跨日段发团不强制拆日；一键生成仅对需要按日的团使用；迁移策略实现期另定。

## Testing Decisions

- 只测外部行为：给定发团日期与操作，断言段数量/日期、资源锚点（段 vs 发团）、应付是否可生成、班组校验（错类别不可存）、票型提示是否出现、台账合计是否等于概览其他收入。
- 主模块：发团执行安排编排（含概览其他收入读取）。
- 先验：现有行程段/段资源 CRUD、资源生成应付、发团概览 API/e2e、供应商类别筛选。
- 验收场景举例：
  - 10 日出团～回团 → 一键生成 10 个一日段。
  - 某日挂酒店+门票+拼出；发团级挂用车/保险/导游并可生成应付。
  - 票型合计 ≠ 客源人数 → 提示且仍可保存。
  - 司机选非用车供应商 / 导游选非导游供应商 → 拒绝保存。
  - 选班组后无新应付节点；团上收入两行合计出现在概览其他收入；无自动应收/流水。

---

## Out of Scope

- 独立「行程日报 / 日报表」实体或与执行安排并行的第二套工作台。
- 班组选择自动生成或草稿化导游/用车应付。
- 团上收入自动生成其他应收，或用流水推导概览其他收入。
- 团上收入品类枚举或组织级品类配置。
- 供应商档案上的车牌/驾驶员字段管理。
- 段级（非发团级）多班组轮换（本迭代仅发团级一组司机+导游）。
- 票型与客源人数硬拦禁止保存（默认可保存+提示）。
- 将团上收入并入当前毛利主指标（本迭代单独「其他收入」卡；是否进毛利后置）。
- 重做整张纸质日报 Excel 版式克隆（运营表增强以系统事实为准，不追求单元格一一对应）。

- 分支建议：`0728行程日报调整`。
- 客户参照物：纸质「天吐喀伊10日日报表」等——按日地点与票型、全程车费/保险/导服、标题司机导游、右下角车销/签单类收入。
- 与既有 CONTEXT 张力：实现时必须改词条，避免代理仍读到「第一版不做每日行程/班组仅备注」而拒做本 PRD。
- 发团改期与「重新一键生成」是否覆盖已有资源：建议默认 **不覆盖已有资源的段**，仅补缺失日或明确二次确认后重建空段；实现计划阶段写清。
