# 核销管理功能设计说明

## 一、功能定位

核销管理用于将**收支流水**与**应收单、应付单**进行匹配，形成可追溯的财务处理记录。

第一版主要解决以下问题：

1. 财务收到一笔款后，可以匹配到对应应收单。
2. 财务支付一笔款后，可以匹配到对应应付单。
3. 系统自动更新流水、应收、应付的已核销金额和未结金额。
4. 系统保留完整核销履历，支持查看和撤销。

第一版不做：

1. 自动核销。
2. 批量核销。
3. 手续费拆分。
4. 坏账处理。
5. 凭证附件。
6. 审批流。
7. 核销记录编辑。

---

## 二、第一版功能范围

第一版只做三个操作入口：

| 入口 | 按钮名称 | 说明 |
|---|---|---|
| 核销管理 | 新增核销 | 财务主动选择流水和账款单进行核销 |
| 收支流水 | 去核销 | 从某一笔流水出发，匹配应收或应付 |
| 应收 / 应付管理 | 匹配流水 | 从某一张账款单出发，匹配收款或付款流水 |

第一版核心能力：

| 功能 | 是否实现 |
|---|---|
| 核销管理列表 | 是 |
| 新增核销 | 是 |
| 收支流水去核销 | 是 |
| 应收匹配流水 | 是 |
| 应付匹配流水 | 是 |
| 查看核销详情 | 是 |
| 撤销核销 | 是 |
| 状态自动更新 | 是 |
| 多账款单核销 | 建议底层支持，前端可第一版简化 |

## 三、核心业务关系

核销记录连接三个对象：

| 对象 | 说明 |
|---|---|
| 收支流水 | 实际发生的收款或付款 |
| 应收 / 应付单 | 系统中待收或待付的账款 |
| 核销记录 | 记录某笔流水核销了哪张账款单、核销了多少钱 |

核销成功后，同步更新以下数据：

| 更新对象 | 更新内容 |
|---|---|
| 收支流水 | 已核销金额、未核销金额、核销状态 |
| 应收单 | 已收金额、未收金额、应收状态 |
| 应付单 | 已付金额、未付金额、应付状态 |
| 核销记录 | 新增正常状态记录 |

## 四、编号规则

### 4.1 核销单号推荐规则

核销单号使用：

**CL + 组织业务前缀 + 年月 + 6位流水号**

示例：

| 组织业务前缀 | 核销单号示例 |
|---|---|
| XTB | CLXTB202607000001 |
| SLD | CLSLD202607000001 |
| TYL | CLTYL202607000001 |

### 4.2 编号含义

| 编号段 | 含义 |
|---|---|
| CL | 核销单固定前缀，可理解为 Clearing / Clear |
| 组织业务前缀 | 每个组织独立配置的业务编码 |
| 年月 | 核销单创建年月，格式为 yyyyMM |
| 6位流水号 | 当前组织、当前年月下的递增序号 |

### 4.3 使用 CL 的原因

核销单的作用是把一笔或多笔资金流水，匹配到一笔或多笔应收、应付单据上，本质属于财务处理记录。

财务中心建议形成统一编号体系：

| 编号 | 含义 |
|---|---|
| AR | 应收单 |
| AP | 应付单 |
| TX | 交易流水 |
| CL | 核销单 |

这样财务对象识别更清晰，也方便后续扩展退款单、结算单、调整单等其他财务单据。

### 4.4 核销单号生成规则

| 项目 | 规则 |
|---|---|
| 编号前缀 | CL |
| 组织前缀 | 使用组织业务前缀 |
| 日期规则 | 年月，格式 yyyyMM |
| 流水位数 | 6 位 |
| 递增规则 | 按组织、年月独立递增 |
| 是否允许修改 | 不允许 |
| 是否允许手动录入 | 不允许 |
| 是否作为主键 | 不作为数据库主键 |
| 生成时机 | 点击确认核销且后端校验通过后生成 |

### 4.5 编号示例

假设组织业务前缀为 **XTB**，2026 年 7 月生成核销单：

| 顺序 | 核销单号 |
|---|---|
| 第一张核销单 | CLXTB202607000001 |
| 第二张核销单 | CLXTB202607000002 |
| 第三张核销单 | CLXTB202607000003 |

### 4.6 财务编号体系汇总

| 业务对象 | 编号规则 | 示例 |
|---|---|---|
| 团单编号 | 组织前缀 + 年月 + 4位流水 | XTB2026070001 |
| 应收单号 | AR + 组织前缀 + 年月 + 6位流水 | ARXTB202607000001 |
| 应付单号 | AP + 组织前缀 + 年月 + 6位流水 | APXTB202607000001 |
| 交易流水号 | TX + 组织前缀 + 年月日 + 6位流水 | TXXTB20260708000001 |
| 核销单号 | CL + 组织前缀 + 年月 + 6位流水 | CLXTB202607000001 |

### 4.7 并发要求

同一组织、同一月份下核销单号不能重复。

建议后端按以下维度维护编号递增：

| 维度 | 说明 |
|---|---|
| org_id | 组织 ID |
| biz_prefix | 组织业务前缀 |
| bill_type | 单据类型，核销单为 CL |
| period | 年月，例如 202607 |

建议使用编号规则表或流水号表，并通过数据库事务、行锁或唯一索引保证并发安全。

核销单号建议增加唯一约束：

**org_id + writeoff_no 唯一**

## 六、新增核销

### 6.1 入口说明

从核销管理页面点击 **新增核销**，打开右侧抽屉。

该入口无预选流水、无预选账款单，用户需要手动完成：

1. 选择核销方向。
2. 选择流水。
3. 选择账款单。
4. 确认核销金额。
5. 提交核销。

### 6.2 抽屉结构

建议右侧抽屉宽度为 720px 至 860px。

抽屉分为四块：

1. 核销基础信息。
2. 选择流水。
3. 匹配账款单。
4. 本次核销确认。

### 6.3 核销基础信息

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 核销方向 | 单选 | 是 | 应收核销、应付核销 |
| 核销日期 | 日期 | 是 | 默认当天 |
| 关联团单 | 搜索选择 | 否 | 用于缩小流水和账款单范围 |
| 交易对象 | 搜索选择 | 否 | 用于缩小流水和账款单范围 |

核销方向规则：

| 核销方向 | 可选流水 | 可匹配账款 |
|---|---|---|
| 应收核销 | 收入流水 | 应收单 |
| 应付核销 | 支出流水 | 应付单 |

### 6.4 选择流水

点击 **选择流水** 后，弹出流水选择弹窗。

#### 流水选择查询条件

| 字段 | 说明 |
|---|---|
| 交易日期 | 默认近 30 天 |
| 交易对象 | 从基础信息带入，可修改 |
| 关联团单 | 从基础信息带入，可修改 |
| 流水号 | 支持搜索 |
| 金额范围 | 可选 |
| 核销状态 | 默认只展示未核销、部分核销 |

#### 可选流水列表字段

| 字段 | 说明 |
|---|---|
| 流水号 | 收支流水编号 |
| 交易日期 | 实际收付款日期 |
| 收支方向 | 收入、支出 |
| 交易对象 | 客户或供应商 |
| 关联团单 | 可为空 |
| 流水金额 | 流水总金额 |
| 已核销金额 | 已匹配金额 |
| 可核销余额 | 流水金额减已核销金额 |
| 账户 | 微信、支付宝、银行卡、现金等 |
| 备注 | 流水备注 |

#### 选择流水后的展示

抽屉展示已选流水信息卡：

| 字段 | 说明 |
|---|---|
| 流水号 | 自动带出 |
| 交易日期 | 自动带出 |
| 收支方向 | 自动带出 |
| 交易对象 | 自动带出 |
| 关联团单 | 自动带出 |
| 流水金额 | 自动带出 |
| 已核销金额 | 自动带出 |
| 可核销余额 | 自动计算 |
| 收付款账户 | 自动带出 |

选择流水后，系统自动刷新可匹配账款单。

### 6.5 匹配账款单

#### 匹配规则

| 条件 | 说明 |
|---|---|
| 核销方向 | 应收核销只展示应收单，应付核销只展示应付单 |
| 交易对象 | 优先匹配同一客户或供应商 |
| 关联团单 | 优先匹配同一团单 |
| 未结金额 | 只展示未结金额大于 0 的账款单 |
| 状态 | 排除已关闭、已结清单据 |
| 金额 | 未结金额等于流水可核销余额时标记推荐 |

#### 账款单列表字段

| 字段 | 应收核销展示 | 应付核销展示 |
|---|---|---|
| 账款单号 | 应收单号 | 应付单号 |
| 类型 | 团款、补款、调整款 | 酒店、用车、门票、导游、餐饮、其他 |
| 交易对象 | 客户 | 供应商 |
| 关联团单 | 团号、团名 | 团号、团名 |
| 账款金额 | 应收金额 | 应付金额 |
| 已核销金额 | 已收金额 | 已付金额 |
| 未结金额 | 未收金额 | 未付金额 |
| 约定日期 | 约定收款日期 | 约定付款日期 |
| 推荐标识 | 推荐匹配 | 推荐匹配 |

### 6.6 本次核销确认

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 本次核销总金额 | 金额 | 是 | 系统自动合计 |
| 每张账款单核销金额 | 金额 | 是 | 可手动修改 |
| 核销后流水余额 | 金额 | 自动 | 流水可核销余额减本次核销总金额 |
| 核销后账款未结金额 | 金额 | 自动 | 每张账款单分别计算 |
| 备注 | 文本 | 否 | 差额、抹零、线下说明 |
| 确认核销 | 按钮 | 是 | 提交核销 |

### 6.7 金额默认规则

当选择一张账款单时：

**本次核销金额 = min（流水可核销余额，账款未结金额）**

当选择多张账款单时：

系统按选择顺序自动分配金额，直到流水余额用完。

第一版前端可以先只支持一笔流水核销一张账款单，但后端模型建议预留多账款单核销能力。

## 七、收支流水去核销

### 7.1 入口位置

在收支流水列表中，对以下状态展示 **去核销**：

| 流水核销状态 | 是否显示 |
|---|---|
| 未核销 | 显示 |
| 部分核销 | 显示 |
| 已核销 | 不显示 |
| 已作废 | 不显示 |

### 7.2 收支流水列表需补充字段

| 字段 | 说明 |
|---|---|
| 流水金额 | 原有字段 |
| 已核销金额 | 新增 |
| 未核销金额 | 新增 |
| 核销状态 | 未核销、部分核销、已核销 |
| 操作 | 去核销、查看核销记录 |

### 7.3 点击去核销后的逻辑

打开新增核销抽屉，并自动带入当前流水。

系统根据流水方向自动判断核销方向：

| 流水方向 | 自动核销方向 |
|---|---|
| 收入 | 应收核销 |
| 支出 | 应付核销 |

抽屉中：

| 区域 | 状态 |
|---|---|
| 核销方向 | 自动带出，不建议修改 |
| 已选流水 | 自动带出 |
| 可匹配账款单 | 自动加载 |
| 本次核销金额 | 自动计算 |

### 7.4 用户操作流程

1. 点击流水列表中的 **去核销**。
2. 系统打开抽屉并带入流水。
3. 用户选择匹配的应收或应付单。
4. 系统自动计算本次核销金额。
5. 用户确认或调整核销金额。
6. 点击 **确认核销**。
7. 系统生成核销记录并更新相关状态。

| 来源 | 自动核销方向 | 可选流水 |

### 8.5 用户操作流程

6. 点击 **确认核销**。
7. 系统生成核销记录并更新相关状态。

## 九、状态设计

### 9.1 核销记录状态

| 状态 | 说明 |
|---|---|
| 正常 | 核销成功后的默认状态 |
| 已撤销 | 核销记录被撤销 |

状态流转：

**正常 → 已撤销**

核销记录不支持编辑。金额错误时只能撤销后重新核销。

### 9.2 流水核销状态

| 状态 | 判断规则 |
|---|---|
| 未核销 | 已核销金额 = 0 |
| 部分核销 | 已核销金额 > 0 且已核销金额 < 流水金额 |
| 已核销 | 已核销金额 = 流水金额 |

流水字段计算：

| 字段 | 计算方式 |
|---|---|
| 已核销金额 | 关联正常核销记录金额合计 |
| 未核销金额 | 流水金额减已核销金额 |
| 核销状态 | 根据金额自动判断 |

### 9.3 应收状态

| 状态 | 判断规则 |
|---|---|
| 待收款 | 已收金额 = 0 |
| 部分收款 | 已收金额 > 0 且已收金额 < 应收金额 |
| 已收清 | 已收金额 = 应收金额 |
| 已关闭 | 人工关闭，不参与新增核销 |

应收字段计算：

| 字段 | 计算方式 |
|---|---|
| 已收金额 | 关联正常核销记录金额合计 |
| 未收金额 | 应收金额减已收金额 |
| 应收状态 | 根据金额自动判断 |

### 9.4 应付状态

| 状态 | 判断规则 |
|---|---|
| 待付款 | 已付金额 = 0 |
| 部分付款 | 已付金额 > 0 且已付金额 < 应付金额 |
| 已付清 | 已付金额 = 应付金额 |
| 已关闭 | 人工关闭，不参与新增核销 |

应付字段计算：

| 字段 | 计算方式 |
|---|---|
| 已付金额 | 关联正常核销记录金额合计 |
| 未付金额 | 应付金额减已付金额 |
| 应付状态 | 根据金额自动判断 |

## 十、确认核销校验规则

| 校验项 | 规则 |
|---|---|
| 核销方向 | 必填 |
| 核销日期 | 必填 |
| 流水 | 必须选择 |
| 账款单 | 必须选择 |
| 核销金额 | 必须大于 0 |
| 流水余额 | 核销总金额不能超过流水可核销余额 |
| 账款余额 | 单张账款核销金额不能超过未结金额 |
| 收入流水 | 只能匹配应收单 |
| 支出流水 | 只能匹配应付单 |
| 已结清账款单 | 不允许核销 |
| 已关闭账款单 | 不允许新增核销 |
| 已完全核销流水 | 不允许核销 |
| 已作废流水 | 不允许核销 |

所有金额校验以后端为准，前端只做提示和辅助计算。

## 十一、撤销核销

### 11.1 入口

核销管理列表中，状态为 **正常** 的记录展示 **撤销核销**。

### 11.2 撤销弹窗字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 核销单号 | 展示 | 是 | 不可修改 |
| 本次核销金额 | 展示 | 是 | 不可修改 |
| 撤销原因 | 文本 | 是 | 必填 |
| 确认撤销 | 按钮 | 是 | 二次确认 |

### 11.3 撤销后处理

撤销后系统需要回滚：

| 对象 | 回滚内容 |
|---|---|
| 核销记录 | 状态改为已撤销，记录撤销人、撤销时间、撤销原因 |
| 收支流水 | 减少已核销金额，重新计算未核销金额和核销状态 |
| 应收单 | 减少已收金额，重新计算未收金额和状态 |
| 应付单 | 减少已付金额，重新计算未付金额和状态 |

### 11.4 撤销限制

| 场景 | 处理 |
|---|---|
| 已撤销记录 | 不允许重复撤销 |
| 流水已作废 | 允许撤销核销，但记录操作日志 |
| 账款单已关闭 | 允许撤销，撤销后账款状态仍保持已关闭 |
| 相关数据被删除 | 第一版不允许删除已核销相关单据 |

## 十六、开发注意事项

1. 核销记录不允许编辑，只允许撤销。
2. 金额计算必须以后端为准。
3. 前端金额计算只用于展示和交互提示。
4. 新增核销必须使用事务。
5. 撤销核销必须使用事务。
6. 核销记录、流水、应收、应付金额必须同时成功或同时失败。
7. 应收、应付、流水状态由后端根据金额自动计算。
8. 所有金额字段保留两位小数。
9. 已核销相关的流水、应收、应付单据第一版不允许物理删除。
10. 核销单号不能作为数据库主键。
11. 多组织数据必须严格隔离。
12. 新增核销提交需要防重复点击。
13. 同一组织同一月份核销单号必须唯一。
14. 已撤销核销记录不参与金额统计。
15. 已撤销核销记录不参与状态计算。
16. 核销详情中需要保留撤销信息，方便财务追溯。

## 十八、推荐第一版实现策略

第一版前端建议先做简单稳定版本：

1. 一次只选择一笔流水。
2. 一次只核销一张应收或应付单。
3. 核销金额默认自动计算，允许用户小于默认金额。
4. 不允许超过流水可核销余额。
5. 不允许超过账款未结金额。
6. 出错时只能撤销后重新核销。
7. 后端数据结构预留一笔流水核销多张账款单的能力。

这样第一版操作简单、开发风险低，也能覆盖大部分中小地接社的财务核销场景。

## 十九、交付说明

开发实现时需重点遵循以下原则：

1. **核销记录不允许编辑，只能撤销重做。**
2. **金额和状态必须以后端计算为准。**
3. **核销单号按组织、年月独立递增，不能重复。**
4. **新增核销和撤销核销必须保证事务一致性。**
