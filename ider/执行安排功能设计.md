# 执行安排功能设计

> 领域术语见 `CONTEXT.md` 与 `docs/adr/0002-departure-domain-model.md`。  
> 段内资源与应付细则见《[资源安排功能设计](./资源安排功能设计.md)》。

## 一、功能定位

**执行安排**是发团详情中规划行程段与段内资源（含自营与拼出）的工作区；详情页 Tab 正式称「执行安排」。

区内称谓（非独立 Tab）：

| 称谓 | 对应 | 说明 |
|---|---|---|
| 行程段 | Itinerary Segment | 左侧段导航 |
| 资源安排 | Segment Resource 列表 | 右侧资源主表 |

行程段按 **日期、目的地** 切分发团，是成本侧锚点。段内通过资源安排维护费用行——用车、酒店、拼出给同行等均为资源。

示例：

| 行程段 | 日期 | 目的地 |
|---|---|---|
| 喀纳斯段 | 7月1日到7月3日 | 喀纳斯 |
| 阿勒泰段 | 7月4日到7月10日 | 阿勒泰 |

第一版重点：

1. 这段行程从哪天到哪天、去哪里。
2. 适用人数（默认取发团总人数）。
3. 段内资源（含拼出）挂在本段下，与段同屏操作。
4. 应付从资源行 **显式生成**，不在行程段层级单独维护拼出字段。

**不设段级「执行方式」**——同一段内可同时有自营资源（Supplier）和拼出资源（Partner）。

主路径：

```text
打开执行安排 → 选中行程段 → 添加资源（含拼出）→ 显式生成应付
```

无段时先添加行程段，再安排资源。

## 二、页面结构

嵌在发团详情 **执行安排** Tab，主从同屏：

```text
极简汇总条
┌─────────────┬──────────────────────────────┐
│ 行程段（窄） │ 资源安排（主表）               │
│ 段导航列表   │ 当前段上下文 + 资源表 / 空态   │
│ + 添加入口   │ + 添加资源                     │
└─────────────┴──────────────────────────────┘
```

段 CRUD 用抽屉；资源 CRUD / 生成应付细则见《资源安排功能设计》。

## 三、极简汇总条

全团只读指标，**不放主按钮**（添加操作下沉到各区）。

展示示例：

**2 段 · 5 项资源 · 应付部分付款**

| 指标 | 说明 |
|---|---|
| 段数 | 当前发团行程段数量 |
| 资源项 | 所有段内资源行合计（含拼出） |
| 应付概况 | 全团派生文案，见下表 |

应付概况与现有 `payableOverview` / `SegmentPayableStatus` 展示文案对齐：

| 取值 | 汇总条文案 |
|---|---|
| `not_generated` | 应付未生成 |
| `pending` | 应付待付 |
| `partial` | 应付部分付款 |
| `paid` | 应付已付清 |

不展示总天数、当前段长上下文、双主按钮。当前段上下文由左侧选中态 + 右侧资源区副文案承担。

## 四、布局与添加入口

| 区域 | 内容 | 添加入口 |
|---|---|---|
| 左侧（窄） | 行程段导航列表 | 「添加行程段」（标题栏或列表底） |
| 右侧（主） | 当前段资源主表 | 「添加资源」（资源区标题栏） |

空态：

| 状态 | 右侧表现 |
|---|---|
| 发团尚无行程段 | Empty「请先添加行程段」+ 主按钮「添加行程段」 |
| 已选段但本段无资源 | Empty「本段暂无资源」+ 主按钮「添加资源」 |

发团只读（已结清 / 已关闭）时隐藏添加与编辑入口。

## 五、URL 与选中规则

Tab key：`execution`。查询参数：

| 参数 | 说明 |
|---|---|
| `tab=execution` | 打开执行安排 |
| `segmentId` | 当前选中行程段；缺省时默认选中排序后的第一段 |

规则：

| 场景 | 行为 |
|---|---|
| 进入 Tab 且无 `segmentId` | 选中第一段（按开始日升序）；无段则空态 |
| 点击左侧某段 | 选中该段，并同步写入 `segmentId` |
| `segmentId` 无效或不属于本发团 | 静默回退到第一段（或空态），并修正 URL |
| 新建行程段保存成功 | 选中新建段，并写入 `segmentId` |
| 删除当前选中段 | 选中相邻下一段；若无下一段则上一段；若无段则空态并清除 `segmentId` |

一次切到新方案：**不写**旧 `segments` / `resources` Tab 与 URL 兼容。

## 六、行程段导航

左侧为精简导航（非宽表），按 **开始日期升序**。

### 1. 展示内容

| 内容 | 说明 |
|---|---|
| 行程段名称 | 如喀纳斯段 |
| 短日期 + 天数 | 如 `07-01–07-03 · 3天` |
| 目的地 | 当前段主要目的地 |
| 模板标签 | 由常用路线带入时显示「模板」 |
| 资源概况 | 如「资源5项｜拼出2条｜¥3,600」 |

不在导航项上展示应付状态列、查看入口、或「资源安排」跳转（资源已在右侧同屏）。

### 2. 操作

| 操作 | 位置 | 说明 |
|---|---|---|
| 选中 | 点击导航项 | 切换右侧资源表 |
| 编辑 | 导航项上的编辑图标 | 打开编辑抽屉 |
| 删除 | 仅在编辑抽屉内 | 导航项不放删除 |

## 七、添加 / 编辑行程段抽屉

### 1. 基础信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 行程段名称 | 是 | 如喀纳斯段 |
| 开始日期 | 是 | 必须在发团日期范围内 |
| 结束日期 | 是 | 必须在发团日期范围内 |
| 天数 | 自动 | 系统计算 |
| 目的地 | 是 | 文本输入 |
| 适用人数 | 是 | 默认取发团总人数，可修改 |
| 备注 | 否 | 特殊说明 |

新建保存后提示：请在本段「资源安排」中添加用车、酒店、拼出等资源。

**不在行程段表单中录入拼出金额或承接同行**——拼出作为资源种类在资源安排中维护。

### 2. 编辑规则

| 场景 | 规则 |
|---|---|
| 段内无资源 / 资源均未生成应付 | 全部字段可编辑 |
| 段内存在已生成应付且未付款的资源 | 改日期/人数时提示复核资源；资源金额变更同步应付 |
| 段内存在已付款资源 | 对应资源金额不可改 |
| 发团已结清 | 只读 |
| 发团已关闭 | 只读 |

### 3. 删除

| 条件 | 说明 |
|---|---|
| 可删 | 段内无资源，或资源均未生成应付 |
| 不可删 | 段内已有资源（含已生成应付）——提示「当前行程段已有资源，不能删除」 |

删除入口仅在抽屉内；删除后的选中规则见第五节。

### 4. 校验

| 场景 | 提示 |
|---|---|
| 行程段名称为空 | 请填写行程段名称 |
| 日期超出发团范围 | 行程段日期不能超出发团日期 |
| 结束日期早于开始日期 | 结束日期不能早于开始日期 |
| 适用人数 < 1 | 适用人数必须大于0 |
| 删除有资源的行程段 | 当前行程段已有资源，不能删除 |

## 八、右侧资源区（总览约定）

本区产品行为细则以《资源安排功能设计》为准。总览层约定：

1. 展示 **当前选中段** 的资源主表；副文案示例：`喀纳斯段 · 适用 18 人 · 3 项`。
2. 第一版 **不做** 资源筛选。
3. 「添加资源」在右侧标题栏；无段时不展示该按钮（见空态）。
4. 资源业务规则（种类、对手方、0 元可存不可生成应付、生成应付后留页 + Toast 等）沿用资源文档，不在本文展开。

---

## 九、完成度信号

发团头部 / 列表的完成度仍分 **「段 / 资源」** 两信号；状态机细则沿用现逻辑，本规格不重设计。

---

## 十、第一版不做

| 不做 | 说明 |
|---|---|
| 日历视图、拖拽排序、每日行程明细 | 段导航按开始日升序即可 |
| 资源筛选、批量生成应付 | 资源区第一版无筛选 |
| 窄屏 / 响应式断点设计 | 以桌面主从布局为准 |
| 旧 `segments` / `resources` Tab 与 URL 兼容 | 一次切换到 `execution` |
| 段级执行方式、段级拼出金额、段级生成应付 | 应付仅在资源行触发 |
| 文档 vs 实现差距清单、验收用例 | 不在本规格范围 |
