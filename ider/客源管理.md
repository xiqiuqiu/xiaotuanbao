# 客源管理

> 领域术语见 `CONTEXT.md` 与 `docs/adr/0002-departure-domain-model.md`。**客源单**（Source Order）= 发团内收入侧结算单元。

## 一、第一版定位

客源管理用于记录当前发团里 **每家合作旅行社输送的客人**、对应团款、优惠、收款拆分，并作为后续 **显式生成应收** 的来源。

第一版保持轻量，主线：

```text
添加客源单 → 录入客户和人数 → 录入团款与优惠 → 录入收款拆分 → 生成应收
```

说明：保存客源单 **不会** 自动生成收付款节点。

## 二、核心命名

| 原概念 | 第一版名称 | 说明 |
|---|---|---|
| 组团社 | 客户 | 对地接社来说，对接方就是客户（领域：Partner） |
| 客源批次 / 客源记录 | **客源单** | 页面可直接叫「客源」 |
| 客源名称 | 系统自动生成 | 用户不需要手动填写 |
| 组团社已收押金 | 客户已收金额 | 合作方已向客人收取的金额 |
| 地接代收金额 | 我方代收金额 | 地接社需直接向客人收取的金额 |
| 收款责任 | 收款方式 | 表达当前客源单的钱款拆分方式 |

## 三、页面结构

嵌在发团详情 Tab 内：

**轻量汇总条 + 筛选区 + 客源单列表 + 添加/编辑抽屉 + 客人名单**

不做大汇总卡，不做客源状态，不做批量操作，不做批量导出。

## 四、轻量汇总条

展示示例：

**客源4单｜总人数18人｜客户3家｜优惠 ¥1,440｜结算金额 ¥18,000｜我方代收 ¥14,400**

| 指标 | 说明 |
|---|---|
| 客源数量 | 当前客源单数 |
| 总人数 | 成人人数 + 儿童人数合计 |
| 客户数量 | 涉及多少个 Partner |
| 优惠合计 | 所有客源单优惠金额合计 |
| 结算金额 | 优惠后应收基数合计 |
| 我方代收 | 地接社需直接向客人收取的金额合计 |

## 五、筛选功能

| 筛选项 | 类型 | 说明 |
|---|---|---|
| 客户 | 下拉搜索 | 按发客 Partner 筛选 |
| 收款方式 | 下拉 | 全部我方代收、客户已收 + 我方代收、客户结算 |
| 是否有优惠 | 下拉 | 全部、有优惠、无优惠 |

按钮：查询、重置

## 七、客源单名称自动生成

规则：**客户名称 + 出团日期 + 发客**

同一 Partner 在同一发团有多条时加序号：`西安某旅行社 7月1日发客 2`

## 八、添加客源单抽屉

### 1. 基础信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 客户 | 是 | 选择 Partner |
| 成人人数 | 是 | ≥ 0；与儿童人数合计须 ≥ 1 |
| 儿童人数 | 否 | 默认 0，可空（按 0）；≥ 0；与成人人数合计须 ≥ 1 |
| 总人数 | 自动 | 成人人数 + 儿童人数 |
| 备注 | 否 | 免票、特殊要求等 |

新建默认成人/儿童均为 0；儿童可不填；总人数 < 1 无法保存。

### 2. 团款与优惠

| 字段 | 必填 | 说明 |
|---|---|---|
| 成人团款单价 | 条件 | 成人人数 > 0 时必填；可为 0 |
| 儿童团款单价 | 条件 | 儿童人数 > 0 时必填；可为 0 |
| 原始团款金额 | 自动 | 成人人数 × 成人团款单价 + 儿童人数 × 儿童团款单价（即原始应收） |
| 优惠方式 | 是 | 无优惠、整单优惠 |
| 优惠金额 | 条件必填 | 整单优惠时填写 |
| 优惠备注 | 否 | 记录优惠说明 |
| 结算金额 | 自动 | 原始应收减优惠金额 |

### 3. 收款信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 收款方式 | 是 | 全部我方代收、客户已收 + 我方代收、客户结算 |
| 客户已收金额 | 条件必填 | 合作方已向客人收取的金额 |
| 我方代收金额 | 条件必填 | 地接社需直接向客人收取的金额 |
| 结算说明 | 否 | 如客户已收部分年底统一结算 |

### 4. 收款方式规则

| 收款方式 | 客户已收金额 | 我方代收金额 | 说明 |
|---|---|---|---|
| 全部我方代收 | 0 | = 结算金额 | 地接向客人收全款 |
| 客户已收 + 我方代收 | 用户填写 | 结算金额 − 客户已收 | 分两段收 |
| 客户结算 | = 结算金额 | 0 | 合作方已收全款，后续与合作方结算 |

**客户已收金额** 也需进入应收跟踪——这部分最终仍需要合作方与地接社结算（**客户补款** 路径）。

**地接全收后需付合作方**：第一版 **不** 在客源单自动生成对 Partner 的应付；财务在应付管理中手动录入（见 ADR-0002）。

## 九、生成应收规则

点击 **生成应收** 后，按收款拆分创建收付款节点（`direction = receivable`）：

| 路径 | 条件 | 标题 | 往来对象 | 说明 |
|---|---|---|---|---|
| **客户补款** | 客户已收金额 > 0 | 客户补款 | 发客 Partner | 合作方已代收、地接需向合作方收取的部分 |
| **游客代收** | 我方代收金额 > 0 | 游客代收 | 游客档案 | 地接需直接向游客收取的部分 |

- 两条路径 **不可合并**——往来对象与跟进责任不同
- 金额为 0 的路径 **不建节点**
- 保存客源单 ≠ 生成应收；已 finance-touched 的节点不因源事实变更而静默改金额，显示 **来源差异警示**

## 十、编辑客源单规则

| 情况 | 编辑规则 |
|---|---|
| 未生成应收 | 全部字段可编辑 |
| 已生成应收且未收款 | 可编辑金额，保存后同步更新收付款节点 |
| 已发生收款（finance-touched） | 金额字段禁止修改，只允许修改备注 |
| 已收齐 | 只读 |
| 发团已关闭 | 只读 |

金额字段：成人人数、儿童人数、成人/儿童团款单价、优惠金额、客户已收金额、我方代收金额。

## 十一、列表操作

| 操作 | 说明 |
|---|---|
| 添加客源单 | 新增 |
| 查看 / 编辑 | 查看或修改 |
| 客人名单 | 维护游客明细 |
| 生成应收 | 显式触发，按路径创建收付款节点 |
| 删除 | 未生成应收时允许 |

## 十二、客人名单

辅助信息，非第一版主流程。

| 字段 | 说明 |
|---|---|
| 姓名 | 游客姓名 |
| 手机号 | 可选 |
| 性别 | 男、女、未知 |
| 备注 | 儿童、免票、特殊要求等 |

操作：添加、编辑、删除。名单是计调备忘，不回写客源单人数（无「同步人数」）。

## 十三、金额计算规则

| 项目 | 规则 |
|---|---|
| 原始应收（原始团款金额） | 成人人数 × 成人团款单价 + 儿童人数 × 儿童团款单价 |
| 结算金额 | 原始应收 − 优惠金额 |
| 我方代收金额 | 结算金额 − 客户已收金额 |

## 十四、校验规则

| 场景 | 提示 |
|---|---|
| 客户为空 | 请选择客户 |
| 总人数 < 1 | 总人数必须大于0 |
| 成人人数 > 0 且单价为空 | 成人团款单价不能为空 |
| 儿童人数 > 0 且单价为空 | 儿童团款单价不能为空 |
| 优惠金额 > 原始应收 | 优惠金额不能大于原始应收 |
| 客户已收 > 结算金额 | 客户已收金额不能大于结算金额 |
| 我方代收不匹配 | 我方代收需等于结算金额减客户已收 |
| 已发生收款后改金额 | 当前客源单已发生收款，不允许修改金额 |
| 已生成应收后删除 | 当前客源单已生成应收，不能直接删除 |

## 十五、第一版流程

```text
添加客源单 → 录入团款与收款拆分 → 确认事实 → 生成应收 → 应收管理跟进收款
```
