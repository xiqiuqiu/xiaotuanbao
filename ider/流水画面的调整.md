财务流水业务改修细节梳理
一、改修目标

当前财务流水已经具备基础记录能力，但与应收、应付、核销管理之间的业务闭环还不够完整。建议本次改修目标明确为：

财务流水用于记录真实收付款资金，并作为后续应收、应付核销的基础数据。

也就是说，流水页面不只是记录金额，还要支持后续判断：这笔钱是否已经核销、核销到哪张应收或应付单、还有多少余额可继续核销。

二、财务流水编号规则

当前流水号类似 TR202607070014，建议统一改为：

TX + 组织业务前缀 + 年月日 + 6位流水号

示例：

组织前缀	流水号
XTB	TXXTB20260708000001
SLD	TXSLD20260708000001
TYL	TXTYL20260708000001

生成规则：

项目	规则
固定前缀	TX
组织前缀	使用组织业务前缀
日期规则	年月日，格式 yyyyMMdd
流水位数	6 位
递增规则	按组织、日期独立递增
是否允许修改	不允许
是否手动录入	不允许
是否作为主键	不作为数据库主键

五、新建流水画面改修
5.1 新建流水定位

新建流水用于记录一笔真实发生的收款或付款。

新建流水只生成 TX 交易流水，默认不自动生成核销记录。后续可以通过“去核销”匹配应收或应付。

特殊说明：如果用户从应收、应付页面点击“登记收款 / 登记付款”，则是快捷流程，会同时生成 TX 流水和 CL 核销单。

六、流水状态设计
6.1 流水状态

流水状态用于表示这条流水本身是否有效。

状态	说明
正常	默认状态，可参与核销
已作废	流水无效，不参与新增核销

状态流转：

正常 → 已作废

已作废流水不可恢复，第一版如需降低风险，可以先不做恢复。

6.2 核销状态

核销状态用于表示这笔流水是否已经匹配到账款单。

状态	判断规则
未核销	已核销金额 = 0
部分核销	已核销金额 > 0 且小于流水金额
已核销	已核销金额 = 流水金额

金额计算：

字段	计算方式
已核销金额	关联正常核销记录金额合计
未核销金额	流水金额减已核销金额
七、列表操作规则
7.1 操作按钮
流水状态	核销状态	可用操作

收入	应收核销
支出	应付核销

进入抽屉后，系统展示该流水可匹配的应收或应付单。

查看核销

字段
核销单号
核销方向
账款单号
关联团单
交易对象
本次核销金额
核销状态
核销人
核销时间
编辑

只允许编辑未核销且正常的流水。

可编辑字段建议为：

字段
收支方向
流水金额
交易日期
收付款账户
交易对象
关联团单
流水备注

如果流水已部分核销或已核销，不允许编辑核心字段，避免账务不一致。

作废

只建议允许未核销流水作废。

场景	是否允许作废
未核销	允许
部分核销	不建议直接作废，需先撤销核销

作废时需要填写作废原因。

八、与应收应付的关系
8.1 从财务流水新建

用户在财务流水页面点击 新增流水：

结果：

只生成 TX 流水。
核销状态为未核销。
不生成 CL 核销记录。
可后续点击“去核销”。
8.2 从应收登记收款

用户在应收管理点击 登记收款：

结果：

生成收入流水 TX。
生成核销单 CL。
更新应收已收、未收、状态。
更新流水已核销、未核销、核销状态。
8.3 从应付登记付款

用户在应付管理点击 登记付款：

结果：

生成支出流水 TX。
生成核销单 CL。
更新应付已付、未付、状态。
更新流水已核销、未核销、核销状态。
8.4 从应收应付匹配流水

用户在应收或应付点击 匹配流水：

结果：

使用已有 TX 流水。
生成核销单 CL。
不新增流水。
更新账款单和流水的核销金额与状态。
九、作废规则细化
9.1 作废入口

财务流水列表中，未核销且正常的流水显示 作废。

9.2 作废弹窗字段
字段	类型	必填	说明
流水号	展示	是	不可修改
流水金额	展示	是	不可修改
交易对象	展示	是	不可修改
作废原因	文本域	是	必填
9.3 作废后影响
对象	影响
财务流水	状态改为已作废

应收 / 应付	无影响

如果未来允许已核销流水作废，必须先撤销核销，再作废流水。

十四、最终建议

本次财务流水建议围绕三个关键词改修：

真实资金记录、可核销余额、核销追溯。

第一版最关键的是把以下链路打通：

新增流水生成 TX。
流水可进入“去核销”。
核销成功生成 CL。
回写流水已核销金额、未核销金额和核销状态。
作废只允许未核销流水。
应收应付登记收付款生成 TX 并自动核销。

这样改完后，财务中心的逻辑就会完整闭环：应收 / 应付产生账款，财务流水记录资金，核销管理负责匹配，所有状态自动回写。
